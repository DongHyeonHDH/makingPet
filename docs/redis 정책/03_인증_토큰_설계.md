# 03. 인증 토큰 설계 — 로그아웃 · 블랙리스트 · RTR · OAuth

> ⚠️ 2026-11-17 결정 반영 — 본 박스가 최신, 본문과 충돌 시 박스 우선
> - 로그아웃 API 신설: `POST /api/users/logout`, `POST /api/users/logout-all`
> - Access Token 무효화: Redis **블랙리스트**(jti 단위 + Token Family 단위)
> - Refresh Token: **RTR(Rotation) + Token Family + 재사용 탐지(Reuse Detection)**
> - 토큰 전달: **하이브리드** — Refresh는 HttpOnly 쿠키, Access는 응답 body (확정)
> - Rotation: **엄격한 RTR** — grace window 없음, 사용된 RT는 즉시 무효 (확정, 게임 기능 대비)
> - **단일 기기 로그인**: 새 로그인 시 그 사용자의 기존 Family를 모두 폐기, 밀려난 기기는 `401 SESSION_REPLACED` (확정)
> - 게임 보상 원자 처리·게임 세션 잠금은 `04_게임_동시성_설계.md` 참고
> - OAuth 성공 리다이렉트: `?token=...` 제거 → **쿠키 + `/refresh` 호출** 방식

> 비유: Refresh Token은 **한 번 쓰면 찢어지는 회수권**이다. 같은 회수권이 두 번 들어오면 누군가 복사한 것이므로, 그 회수권 묶음(Family) 전체를 폐기한다.

## 0. 결정 요약

| 영역 | 결정 | 이유 |
|---|---|---|
| Access Token | JWT, 30분, `jti`·`fid` 클레임 추가 | 개별 무효화(jti)와 Family 단위 무효화(fid)를 위해 |
| Access 무효화 | Redis 블랙리스트, TTL = 토큰 남은 수명 | Stateless JWT는 만료 전 강제 폐기 수단이 없음 |
| Refresh Token | **불투명 랜덤 문자열**(JWT 아님), Redis에 **SHA-256 해시만** 저장 | 서버가 상태를 쥐어야 Rotation·재사용 탐지가 가능. 원문 유출 방지 |
| Rotation | 재발급 시 매번 새 Refresh 발급, 이전 것은 `USED` | 탈취된 토큰의 유효 기간을 1회 사용으로 축소 |
| Token Family | 로그인 1회 = Family 1개, Rotation은 같은 Family 안에서 | 재사용 탐지 시 "그 로그인 세션 전체"를 폐기하는 단위 |
| 재사용 탐지 | `USED` 토큰이 다시 오면 Family 전체 `REVOKED` + 그 Family의 Access도 블랙리스트 | 공격자와 정상 사용자 중 누가 원본인지 알 수 없으므로 둘 다 끊는다 |
| 원자성 | Rotation은 **Lua 스크립트 1회**로 처리 | 동시 요청 시 이중 발급·탐지 누락을 막음 |
| 전달 (하이브리드) | Refresh는 `HttpOnly; Secure; SameSite=Strict; Path=/api/users` 쿠키, Access는 응답 body | Refresh는 JS가 읽을 수 없어 XSS로 탈취 불가, Access는 헤더에 실어 보내야 하므로 body |
| Rotation 강도 | 엄격한 RTR, grace window 없음 | 게임 기능 대비. 동시 재발급은 프론트에서 직렬화 |
| 동시 로그인 | 단일 기기(브라우저) 정책, 새 로그인이 이전 세션을 밀어냄 | 게임 재화의 다중 기기 악용 방지. 밀려난 기기는 `SESSION_REPLACED`로 안내 |
| Access 보관(프론트) | **메모리 변수만**, localStorage 금지 | 새로고침 시 `/refresh`로 다시 받음 |
| Redis 장애 | **fail-closed** (토큰이 있는 요청은 503) | 보안 판단을 "모르면 허용"으로 두지 않음 |
| 수명 | Refresh 유휴 7일(sliding), Family 절대 30일 | 계속 쓰면 연장되지만 30일마다 재로그인 |

## 1. 핵심 개념

### 1-1. 왜 블랙리스트가 필요한가
JWT는 서명만 맞으면 서버가 상태 없이 통과시킨다. 그래서 로그아웃해도 Access Token은 **만료(30분)까지 계속 유효**하다. 로그아웃 시점에 해당 토큰의 `jti`를 Redis에 넣고, `JwtFilter`가 매 요청마다 확인한다.
- TTL을 **토큰의 남은 수명**으로 주면 만료된 토큰은 자동으로 블랙리스트에서도 사라진다. 블랙리스트가 무한히 커지지 않는다.

### 1-2. RTR + Token Family + 재사용 탐지

```
로그인 ─▶ Family F 생성 ─▶ RT1 발급 (current = RT1)
/refresh(RT1) ─▶ RT1 = USED, RT2 발급 (current = RT2)
/refresh(RT2) ─▶ RT2 = USED, RT3 발급 (current = RT3)

[탈취 시나리오]
공격자가 RT2를 훔쳤다 → 정상 사용자는 이미 RT2로 RT3를 받음
공격자 /refresh(RT2) ─▶ RT2는 USED ─▶ 재사용 탐지!
   ─▶ Family F = REVOKED
   ─▶ F로 발급된 Access 전부 블랙리스트 (blacklist:family:F)
   ─▶ 정상 사용자 RT3도 다음 /refresh에서 실패 → 재로그인
```
공격자가 먼저 쓰고 정상 사용자가 나중에 써도 결과는 같다. **어느 쪽이 먼저든 두 번째 사용에서 Family가 죽는다.**

### 1-3. 동시 요청 함정 (실무에서 가장 많이 터지는 곳)
엄격한 RTR에서는 **탭 2개가 동시에 같은 RT로 `/refresh`** 하면 두 번째가 재사용으로 판정되어 사용자가 로그아웃된다. 공격이 아닌데도.
- **대책(필수, 프론트)**: 재발급을 하나로 묶는다.
  - 탭 안: 진행 중인 refresh Promise를 공유(single-flight).
  - 탭 사이: `navigator.locks.request('token-refresh', ...)` (Web Locks API)로 한 번에 한 탭만 refresh.
- **grace window는 도입하지 않는다(확정).** 직전 토큰을 N초간 허용하면 그 사이 탈취 토큰도 통과하므로, 게임 기능을 고려해 엄격한 RTR을 유지한다. 따라서 위 프론트 직렬화는 **선택이 아니라 필수**다. 빠지면 정상 사용자가 탭 전환만으로 로그아웃된다.
- 주의: 엄격한 RTR은 "같은 브라우저의 탭 두 개 동시 사용"을 막지 않는다. 탭들은 같은 쿠키(같은 Family)를 공유한다. 동시 플레이 제어가 필요하면 별도 장치(게임 세션 잠금 등)를 둔다.

### 1-4. OAuth 쿼리스트링 토큰의 문제
`{baseUrl}/oauth/callback?token=eyJ...` 방식은 토큰이 다음 곳에 남는다.
- 브라우저 방문 기록, 자동완성
- Nginx / NPM access log (URL 전체가 기록됨)
- 다음 페이지 요청의 `Referer` 헤더, 외부 분석 스크립트
- 사용자가 주소를 복사해서 공유하는 경우

**대책**: 백엔드가 OAuth 성공 시 **Refresh 쿠키만 심고**, 프론트에는 토큰 없이 `{baseUrl}/oauth/callback`으로 보낸다. 프론트는 그 페이지에서 `POST /api/users/refresh`를 호출해 Access Token을 body로 받는다. URL에는 아무 비밀도 남지 않는다.

## 2. 흐름

### 2-1. 로그인
```
Client ── POST /api/users/login {email, password} ──▶ AuthService
  1. 자격 증명 검증 (실패 시 401 LOGIN_FAILED)
  2. 사용자 단위 분산락 획득 (lock:auth:login:{userId})
  3. 기존 Family 전부 폐기 + blacklist:family:{fid} = "replaced"   ← 단일 기기 정책
  4. RefreshTokenService.issue(userId)   → Family F, RT1 (Redis)
  5. 락 해제
  6. TokenProvider.createAccessToken(user, F) → jti=J1, fid=F
◀── 200 body {accessToken, tokenType, expiresIn}
    Set-Cookie: refresh_token=F.<random>; HttpOnly; Secure; SameSite=Strict; Path=/api/users; Max-Age=604800
```

### 2-2. 재발급
```
Client ── POST /api/users/refresh (Cookie: refresh_token) ──▶ AuthService
  1. 쿠키 없음 → 401 REFRESH_TOKEN_MISSING
  2. Lua rotate 스크립트 (원자적)
       OK      → 새 RT + 새 Access (같은 fid)
       REUSED  → Family REVOKED + blacklist:family:F → 401 REFRESH_TOKEN_REUSED (+ 보안 로그)
       EXPIRED → 401 REFRESH_TOKEN_EXPIRED
       INVALID / REVOKED → 401 REFRESH_TOKEN_INVALID
◀── 200 body {accessToken, ...} + Set-Cookie(새 RT)
    실패 시 Set-Cookie: refresh_token=; Max-Age=0  (쿠키 삭제)
```

### 2-3. 로그아웃
```
Client ── POST /api/users/logout (Authorization 선택, Cookie 선택) ──▶ AuthService
  1. Access가 있고 서명 유효 → blacklist:access:{jti}  TTL = 남은 수명
  2. Refresh 쿠키가 있고 실제 존재 → Family REVOKED + blacklist:family:{fid}
◀── 200 (항상 성공, 멱등) + 쿠키 삭제
```
- **Access가 만료된 상태에서도 로그아웃할 수 있어야** 하므로 `permitAll`이다. 인증 실패로 로그아웃을 막으면 Refresh가 서버에 남는다.

### 2-4. 전체 기기 로그아웃
```
POST /api/users/logout-all (✅ USER)
  → user:{id}:families 의 모든 Family REVOKED + 각 Family 블랙리스트 → 쿠키 삭제
```
비밀번호 변경, 계정 정지 시에도 이 메서드를 호출한다.

### 2-5. OAuth 로그인 (개선)
```
Browser ─▶ /oauth2/authorization/google ─▶ Google ─▶ /login/oauth2/code/google
  OauthService: 이메일로 사용자 조회/생성
  OauthSuccessHandler:
     RefreshTokenService.issue(userId) → Set-Cookie refresh_token
     Referrer-Policy: no-referrer
     302 → {baseUrl}/oauth/callback        ← 토큰 없음
Frontend /oauth/callback:
     POST /api/users/refresh (credentials: 'include') → accessToken 수신 → 메모리 저장 → 홈 이동
```
> OAuth 로그인도 `AuthService.issueFor()`를 거치므로 단일 기기 정책이 똑같이 적용된다.

### 2-6. 단일 기기 로그인
```
기기 A 로그인 ─▶ Family FA
기기 B 로그인 ─▶ [락] FA REVOKED + blacklist:family:FA = "replaced" ─▶ Family FB 발급 [락 해제]

기기 A 다음 API 요청   ─▶ JwtFilter: FA 블랙리스트(replaced) ─▶ 401 SESSION_REPLACED
기기 A 재발급 시도     ─▶ FA REVOKED ─▶ 401 REFRESH_TOKEN_INVALID
프론트: SESSION_REPLACED 받으면 "다른 기기에서 로그인되어 로그아웃되었습니다" 안내 후 로그인 화면
```
- **기기 = 브라우저(쿠키 저장소) 단위**다. 같은 브라우저의 탭들은 같은 Family를 공유하므로 서로를 밀어내지 않는다. 탭 간 동시 플레이는 `04_게임_동시성_설계.md`의 게임 세션 잠금이 막는다.
- **분산락이 필요한 이유**: 두 기기가 거의 동시에 로그인하면 "둘 다 기존 폐기 → 둘 다 발급"이 되어 Family가 두 개 살아남는다. 사용자 단위 락으로 "폐기 + 발급"을 한 덩어리로 만든다(Redisson, 이미 의존성 있음).
- 밀려난 기기의 Access는 Family 블랙리스트로 **즉시** 막힌다(최대 30분 기다리지 않음).

## 3. Redis 키 설계

> `{fid}`의 중괄호는 **Redis Cluster 해시 태그**다. 한 Family의 키들이 같은 슬롯에 모여 Lua 스크립트를 쓸 수 있다. 단일 노드에서도 그대로 동작한다.

| 키 | 타입 | 필드 / 값 | TTL | 용도 |
|---|---|---|---|---|
| `auth:family:{fid}` | Hash | `userId`, `status`(ACTIVE/REVOKED/EXPIRED), `currentHash`, `absExp`(epoch초) | 절대 만료까지 | Family 상태, 현재 유효한 RT |
| `auth:rt:{fid}:<sha256>` | Hash | `userId`, `status`(ACTIVE/USED), `issuedAt`, `usedAt` | 유휴 7일 (절대 만료를 넘지 않음) | 개별 RT. USED도 남겨야 재사용 탐지 가능 |
| `auth:user:<userId>:families` | Set | fid 목록 | 30일 (발급 시 갱신) | 전체 로그아웃 |
| `auth:blacklist:access:<jti>` | String | `logout` | Access 남은 수명 | 개별 Access 무효화 |
| `auth:blacklist:family:{fid}` | String | 폐기 사유: `logout` / `logout-all` / `reuse` / `replaced` | Access 유효기간(30분) | Family의 모든 Access 무효화. 사유로 에러 코드를 구분 |
| `lock:auth:login:<userId>` | Redisson 락 | - | 대기 3초, 보유 5초 | 단일 기기 정책의 "폐기 + 발급" 원자화 |

**Refresh Token 형식**: `<fid>.<base64url(32바이트 난수)>`
- `fid`가 앞에 있어 키를 바로 만들 수 있고, 뒤 32바이트(256비트)가 실제 비밀이다.
- Redis에는 **원문 전체의 SHA-256**만 저장한다. Redis가 덤프돼도 RT를 재사용할 수 없다.

**기존 템플릿과의 차이**: `common/security/domain/RefreshToken`(`@RedisHash`) + `RefreshTokenRepository`는 **삭제**한다. Repository 방식으로는 "조회 → 상태 확인 → 교체"를 원자적으로 할 수 없다.

## 4. API 명세 변경

### 4-1. 엔드포인트 목록 (`02_엔드포인트_목록.md` 반영분)

| # | Method | Path | Auth | 요약 | 성공 | 주요 에러 |
|---|---|---|---|---|---|---|
| U-2 | POST | /api/users/login | 🔓 | 로그인 (RT는 쿠키) | 200 | 401 LOGIN_FAILED |
| U-3 | POST | /api/users/refresh | 🔓(쿠키) | 토큰 재발급 + Rotation | 200 | 401 REFRESH_TOKEN_MISSING / INVALID / EXPIRED / REUSED |
| U-5 | POST | /api/users/logout | 🔓 | 현재 세션 로그아웃 | 200 | - |
| U-6 | POST | /api/users/logout-all | ✅ | 모든 기기 로그아웃 | 200 | 401 |

### 4-2. U-2. POST `/api/users/login`
**응답 200**
```http
Set-Cookie: refresh_token=3f1c...e9.Qm9i...; Path=/api/users; Max-Age=604800; HttpOnly; Secure; SameSite=Strict
```
```json
{ "success": true, "message": "계정에 성공적으로 로그인되었습니다.",
  "data": { "accessToken": "eyJ...", "tokenType": "Bearer", "expiresIn": 1800 } }
```
| 필드 | 타입 | 설명 |
|---|---|---|
| accessToken | string | JWT. 프론트는 메모리에만 보관 |
| tokenType | string | 항상 `Bearer` |
| expiresIn | long | Access 수명(초) |

> `refreshToken` 필드는 body에서 **제거**된다(쿠키로만 전달).

### 4-3. U-3. POST `/api/users/refresh`
**요청**: body 없음. `Cookie: refresh_token=...` (프론트는 `credentials: 'include'`)
**응답 200**: U-2와 같은 body + 새 `Set-Cookie`
**에러** (모두 응답에 쿠키 삭제 헤더 포함)

| HTTP | code | 발생 조건 |
|---|---|---|
| 401 | REFRESH_TOKEN_MISSING | 쿠키 없음 |
| 401 | REFRESH_TOKEN_INVALID | 형식 오류, 존재하지 않음, 이미 폐기된 Family |
| 401 | REFRESH_TOKEN_EXPIRED | Family 절대 만료(30일) 도달 |
| 401 | REFRESH_TOKEN_REUSED | 이미 사용된 RT 재사용 → Family 폐기 |
| 503 | AUTH_STORE_UNAVAILABLE | Redis 장애 |

**부수효과**: REUSED 시 Family의 모든 Access Token이 즉시 무효화되고 `[SECURITY]` 경고 로그가 남는다.

### 4-4. U-5. POST `/api/users/logout`
**요청**: `Authorization: Bearer <jwt>`(선택), `Cookie: refresh_token`(선택)
**응답 200**
```json
{ "success": true, "message": "로그아웃되었습니다." }
```
- 토큰이 없거나 이미 무효여도 200 (멱등). 응답에 항상 쿠키 삭제 헤더.

### 4-5. U-6. POST `/api/users/logout-all`
**인증**: USER · **응답 200**: `{ "success": true, "message": "모든 기기에서 로그아웃되었습니다." }`

### 4-6. 에러 코드 사전 추가분 (append-only)

| code | HTTP | 의미 |
|---|---|---|
| TOKEN_REVOKED | 401 | 블랙리스트에 오른 Access Token |
| SESSION_REPLACED | 401 | 다른 기기의 로그인으로 현재 세션이 종료됨 |
| LOGIN_IN_PROGRESS | 409 | 같은 계정의 로그인이 동시에 처리 중 (락 대기 초과) |
| AUTH_STORE_UNAVAILABLE | 503 | 인증 저장소(Redis) 장애, fail-closed |
| REFRESH_TOKEN_MISSING | 401 | Refresh 쿠키 없음 |
| REFRESH_TOKEN_INVALID | 401 | 형식 오류·미존재·폐기된 Family |
| REFRESH_TOKEN_REUSED | 401 | 재사용 탐지, Family 폐기됨 |

> `REFRESH_TOKEN_EXPIRED`, `TOKEN_EXPIRED`, `TOKEN_INVALID`는 기존 코드를 그대로 쓴다.

### 6-4. `AccessTokenBlacklistService`
```java
@Service
@RequiredArgsConstructor
public class AccessTokenBlacklistService {
    private final StringRedisTemplate redis;
    private final JwtProperties props;

    /** 개별 Access 폐기. 남은 수명이 없으면 저장하지 않는다 */
    public void revokeAccess(String jti, Instant expiresAt) {
        Duration remaining = Duration.between(Instant.now(), expiresAt);
        if (remaining.isNegative() || remaining.isZero()) return;
        redis.opsForValue().set(RedisKeys.blacklistAccess(jti), "logout", remaining);
    }

    /** Family로 발급된 모든 Access 폐기. Access 최대 수명만큼만 유지하면 충분 */
    public void revokeFamilyAccess(String familyId, String reason) {
        redis.opsForValue().set(RedisKeys.blacklistFamily(familyId), reason,
                Duration.ofMillis(props.getValidations().getAccess()));
    }

    /**
     * 폐기되었으면 그 사유를, 아니면 empty를 돌려준다.
     * Redis 장애 시 DataAccessException을 그대로 던진다 (호출자가 fail-closed 처리)
     */
    public Optional<String> revocationReason(String jti, String familyId) {
        List<String> keys = (familyId == null)
                ? List.of(RedisKeys.blacklistAccess(jti))
                : List.of(RedisKeys.blacklistAccess(jti), RedisKeys.blacklistFamily(familyId));
        List<String> values = redis.opsForValue().multiGet(keys);
        if (values == null) return Optional.empty();
        return values.stream().filter(Objects::nonNull).findFirst();
    }
}
```
> `multiGet`은 `MGET k1 k2` 한 번이다. Redis Cluster로 가면 두 키의 슬롯이 다르므로 파이프라인으로 바꾼다.

### 6-5. Rotation Lua 스크립트 `resources/redis/rotate_refresh_token.lua`
```lua
-- KEYS[1] = auth:rt:{fid}:<oldHash>
-- KEYS[2] = auth:family:{fid}
-- KEYS[3] = auth:blacklist:family:{fid}
-- KEYS[4] = auth:rt:{fid}:<newHash>
-- ARGV[1] = oldHash, ARGV[2] = newHash, ARGV[3] = now(epoch초)
-- ARGV[4] = 유휴 TTL(초), ARGV[5] = Access TTL(초)
-- 반환: { 결과, userId, 새 RT TTL(초) }

local fam = redis.call('HMGET', KEYS[2], 'status', 'currentHash', 'absExp', 'userId')
if not fam[1] then return { 'INVALID' } end
local userId = fam[4]
if fam[1] ~= 'ACTIVE' then return { 'REVOKED', userId } end

-- 존재하지 않는 RT: 위조/추측. Family는 건드리지 않는다 (fid만 아는 공격자의 강제 로그아웃 방지)
local rtStatus = redis.call('HGET', KEYS[1], 'status')
if not rtStatus then return { 'INVALID', userId } end

-- 재사용 탐지: 이미 쓴 RT이거나, 현재 RT가 아님
if rtStatus ~= 'ACTIVE' or fam[2] ~= ARGV[1] then
  redis.call('HSET', KEYS[2], 'status', 'REVOKED')
  redis.call('SET', KEYS[3], 'reuse', 'EX', ARGV[5])
  return { 'REUSED', userId }
end

local now = tonumber(ARGV[3])
local absExp = tonumber(fam[3])
if now >= absExp then
  redis.call('HSET', KEYS[2], 'status', 'EXPIRED')
  return { 'EXPIRED', userId }
end

-- Rotation
redis.call('HSET', KEYS[1], 'status', 'USED', 'usedAt', ARGV[3])
local ttl = math.min(tonumber(ARGV[4]), absExp - now)
redis.call('HSET', KEYS[4], 'userId', userId, 'status', 'ACTIVE', 'issuedAt', ARGV[3])
redis.call('EXPIRE', KEYS[4], ttl)
redis.call('HSET', KEYS[2], 'currentHash', ARGV[2])
return { 'OK', userId, tostring(ttl) }
```

### 6-6. `RefreshTokenService`
```java
@Slf4j
@Service
@RequiredArgsConstructor
public class RefreshTokenService {
    private static final SecureRandom RANDOM = new SecureRandom();
    private static final RedisScript<List> ROTATE =
            RedisScript.of(new ClassPathResource("redis/rotate_refresh_token.lua"), List.class);

    private final StringRedisTemplate redis;
    private final JwtProperties props;
    private final AccessTokenBlacklistService blacklist;

    public enum Outcome { OK, REUSED, EXPIRED, REVOKED, INVALID }
    public record IssuedRefreshToken(String rawToken, String familyId, Duration ttl) {}
    public record RotationResult(Outcome outcome, Long userId, IssuedRefreshToken newToken) {}

    /** 로그인 1회 = 새 Family */
    public IssuedRefreshToken issue(Long userId) {
        String fid = UUID.randomUUID().toString();
        String raw = fid + "." + randomSecret();
        String hash = sha256(raw);
        long now = Instant.now().getEpochSecond();
        long absoluteSec = props.getValidations().getRefreshAbsolute() / 1000;
        long idleSec = Math.min(props.getValidations().getRefresh() / 1000, absoluteSec);

        redis.opsForHash().putAll(RedisKeys.family(fid), Map.of(
                "userId", userId.toString(), "status", "ACTIVE",
                "currentHash", hash, "absExp", String.valueOf(now + absoluteSec)));
        redis.expire(RedisKeys.family(fid), Duration.ofSeconds(absoluteSec));

        redis.opsForHash().putAll(RedisKeys.refresh(fid, hash), Map.of(
                "userId", userId.toString(), "status", "ACTIVE", "issuedAt", String.valueOf(now)));
        redis.expire(RedisKeys.refresh(fid, hash), Duration.ofSeconds(idleSec));

        redis.opsForSet().add(RedisKeys.userFamilies(userId), fid);
        redis.expire(RedisKeys.userFamilies(userId), Duration.ofSeconds(absoluteSec));
        return new IssuedRefreshToken(raw, fid, Duration.ofSeconds(idleSec));
    }

    public RotationResult rotate(String rawToken) {
        String fid = parseFamilyId(rawToken);
        if (fid == null) return new RotationResult(Outcome.INVALID, null, null);

        String oldHash = sha256(rawToken);
        String newRaw = fid + "." + randomSecret();
        String newHash = sha256(newRaw);
        long now = Instant.now().getEpochSecond();

        List<?> r = redis.execute(ROTATE,
                List.of(RedisKeys.refresh(fid, oldHash), RedisKeys.family(fid),
                        RedisKeys.blacklistFamily(fid), RedisKeys.refresh(fid, newHash)),
                oldHash, newHash, String.valueOf(now),
                String.valueOf(props.getValidations().getRefresh() / 1000),
                String.valueOf(props.getValidations().getAccess() / 1000));

        Outcome outcome = Outcome.valueOf((String) r.get(0));
        Long userId = r.size() > 1 ? Long.valueOf((String) r.get(1)) : null;
        if (outcome == Outcome.REUSED) {
            log.warn("[SECURITY] Refresh Token 재사용 탐지 userId={} familyId={}", userId, fid);
        }
        if (outcome != Outcome.OK) return new RotationResult(outcome, userId, null);

        Duration ttl = Duration.ofSeconds(Long.parseLong((String) r.get(2)));
        return new RotationResult(Outcome.OK, userId, new IssuedRefreshToken(newRaw, fid, ttl));
    }

    /** 로그아웃: 실제 존재하는 RT일 때만 Family 폐기 */
    public void revokeByToken(String rawToken) {
        String fid = parseFamilyId(rawToken);
        if (fid == null) return;
        if (!Boolean.TRUE.equals(redis.hasKey(RedisKeys.refresh(fid, sha256(rawToken))))) return;
        revokeFamily(fid, "logout");
    }

    /** reason: "logout-all" (전체 로그아웃) 또는 "replaced" (단일 기기 정책) */
    public void revokeAllFamilies(Long userId, String reason) {
        Set<String> fids = redis.opsForSet().members(RedisKeys.userFamilies(userId));
        if (fids != null) fids.forEach(fid -> revokeFamily(fid, reason));
        redis.delete(RedisKeys.userFamilies(userId));
    }

    private void revokeFamily(String fid, String reason) {
        if (Boolean.TRUE.equals(redis.hasKey(RedisKeys.family(fid)))) {
            redis.opsForHash().put(RedisKeys.family(fid), "status", "REVOKED");
        }
        blacklist.revokeFamilyAccess(fid, reason);
    }

    private static String parseFamilyId(String raw) {
        if (raw == null) return null;
        int dot = raw.indexOf('.');
        if (dot != 36 || raw.length() < 37 + 43) return null;   // UUID(36) + "." + base64url(32B)=43
        String fid = raw.substring(0, dot);
        try { UUID.fromString(fid); return fid; } catch (IllegalArgumentException e) { return null; }
    }

    private static String randomSecret() {
        byte[] b = new byte[32];
        RANDOM.nextBytes(b);
        return Base64.getUrlEncoder().withoutPadding().encodeToString(b);
    }

    private static String sha256(String s) {
        try {
            return HexFormat.of().formatHex(
                    MessageDigest.getInstance("SHA-256").digest(s.getBytes(StandardCharsets.UTF_8)));
        } catch (NoSuchAlgorithmException e) { throw new IllegalStateException(e); }
    }
}
```

### 6-8. `JwtFilter` (변경)
```java
@Slf4j
@Component
@RequiredArgsConstructor
public class JwtFilter extends OncePerRequestFilter {
    public static final String AUTH_ERROR = "auth.error";
    private final TokenProvider tokenProvider;
    private final AccessTokenBlacklistService blacklist;
    private final UserService userService;

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        String token = extractToken(req);
        if (token == null) { chain.doFilter(req, res); return; }

        TokenProvider.TokenBody body;
        try {
            body = tokenProvider.parseJwt(token);
        } catch (ExpiredJwtException e) {
            req.setAttribute(AUTH_ERROR, ErrorCode.TOKEN_EXPIRED); chain.doFilter(req, res); return;
        } catch (JwtException | IllegalArgumentException e) {
            req.setAttribute(AUTH_ERROR, ErrorCode.TOKEN_INVALID); chain.doFilter(req, res); return;
        }

        try {
            Optional<String> reason = blacklist.revocationReason(body.jti(), body.familyId());
            if (reason.isPresent()) {
                req.setAttribute(AUTH_ERROR, "replaced".equals(reason.get())
                        ? ErrorCode.SESSION_REPLACED : ErrorCode.TOKEN_REVOKED);
                chain.doFilter(req, res);
                return;
            }
        } catch (DataAccessException e) {                      // fail-closed
            log.error("블랙리스트 조회 실패 — 요청 차단", e);
            AuthErrorWriter.write(res, ErrorCode.AUTH_STORE_UNAVAILABLE);
            return;
        }

        CurrentUser user = userService.loadCurrentUserByEmail(body.email());
        SecurityContextHolder.getContext().setAuthentication(
                new UsernamePasswordAuthenticationToken(user, null, user.getAuthorities()));
        chain.doFilter(req, res);
    }

    private String extractToken(HttpServletRequest req) {
        String h = req.getHeader(HttpHeaders.AUTHORIZATION);
        return (h != null && h.startsWith("Bearer ")) ? h.substring(7) : null;
    }
}
```

### 6-10. `AuthService`
```java
@Service
@RequiredArgsConstructor
public class AuthService {
    private final UserService userService;
    private final PasswordEncoder passwordEncoder;
    private final TokenProvider tokenProvider;
    private final RefreshTokenService refreshTokenService;
    private final AccessTokenBlacklistService blacklist;
    private final RedissonClient redisson;
    private final JwtProperties props;

    public record IssuedTokens(LoginResponse body, RefreshTokenService.IssuedRefreshToken refresh) {}

    public IssuedTokens login(LoginRequest request) {
        User foundUser = userService.findByEmail(request.email())
                .filter(u -> passwordEncoder.matches(request.password(), u.getPassword()))
                .orElseThrow(() -> new BusinessException(ErrorCode.LOGIN_FAILED));
        return issueFor(foundUser);
    }

    /**
     * 새 로그인 세션 발급. OAuth 성공 시에도 사용.
     * 단일 기기 정책: 사용자 단위 락 안에서 기존 Family 전부 폐기 후 새 Family 발급
     */
    public IssuedTokens issueFor(User user) {
        RLock lock = redisson.getLock("lock:auth:login:" + user.getId());
        boolean acquired;
        try {
            acquired = lock.tryLock(3, 5, TimeUnit.SECONDS);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new BusinessException(ErrorCode.LOGIN_IN_PROGRESS);
        }
        PreConditions.validate(acquired, ErrorCode.LOGIN_IN_PROGRESS);
        try {
            refreshTokenService.revokeAllFamilies(user.getId(), "replaced");
            var refresh = refreshTokenService.issue(user.getId());
            return new IssuedTokens(toBody(tokenProvider.createAccessToken(user, refresh.familyId())), refresh);
        } finally {
            if (lock.isHeldByCurrentThread()) lock.unlock();
        }
    }

    public IssuedTokens refresh(String rawRefresh) {
        PreConditions.validate(rawRefresh != null && !rawRefresh.isBlank(), ErrorCode.REFRESH_TOKEN_MISSING);
        var result = refreshTokenService.rotate(rawRefresh);
        return switch (result.outcome()) {
            case OK -> {
                User foundUser = userService.getById(result.userId());   // 탈퇴/정지 사용자면 여기서 차단
                yield new IssuedTokens(
                        toBody(tokenProvider.createAccessToken(foundUser, result.newToken().familyId())),
                        result.newToken());
            }
            case REUSED  -> throw new BusinessException(ErrorCode.REFRESH_TOKEN_REUSED);
            case EXPIRED -> throw new BusinessException(ErrorCode.REFRESH_TOKEN_EXPIRED);
            case REVOKED, INVALID -> throw new BusinessException(ErrorCode.REFRESH_TOKEN_INVALID);
        };
    }

    /** 멱등. 어떤 입력이든 예외 없이 끝난다 (Redis 장애 제외) */
    public void logout(String accessToken, String rawRefresh) {
        if (accessToken != null) {
            try {
                var body = tokenProvider.parseJwt(accessToken);
                blacklist.revokeAccess(body.jti(), body.expiresAt());
            } catch (JwtException | IllegalArgumentException ignored) {
                // 만료·위조 토큰은 블랙리스트할 필요 없음
            }
        }
        if (rawRefresh != null) refreshTokenService.revokeByToken(rawRefresh);
    }

    public void logoutAll(Long userId) {
        refreshTokenService.revokeAllFamilies(userId, "logout-all");
    }

    private LoginResponse toBody(String accessToken) {
        return new LoginResponse(accessToken, "Bearer", props.getValidations().getAccess() / 1000);
    }
}
```

```java
    }

    @PostMapping("/logout-all")
    public ApiResponse<Void> logoutAll(@AuthenticationPrincipal CurrentUser currentUser, HttpServletResponse res) {
        authService.logoutAll(currentUser.getId());
        cookies.clear(res);
        return ApiResponse.ok(SuccessCode.USER_LOGOUT_ALL.getSuccessMessage());
    }
}
```

### 6-13. `OauthSuccessHandler` (변경)
```java
@Component
@RequiredArgsConstructor
public class OauthSuccessHandler implements AuthenticationSuccessHandler {
    private final UserService userService;
    private final AuthService authService;
    private final RefreshTokenCookieManager cookies;

    @Value("${custom.baseUrl}") private String baseUrl;

    @Override
    public void onAuthenticationSuccess(HttpServletRequest req, HttpServletResponse res, Authentication auth)
            throws IOException {
        User user = userService.getByEmail(((OAuth2User) auth.getPrincipal()).getAttribute("email"));
        cookies.write(res, authService.issueFor(user).refresh());   // 단일 기기 정책 포함. Access는 /refresh로 받음
        res.setHeader("Referrer-Policy", "no-referrer");
        res.setHeader(HttpHeaders.CACHE_CONTROL, "no-store");
        res.sendRedirect(baseUrl + "/oauth/callback");          // URL에 토큰 없음
    }
}
```
> Naver는 `email`이 `response` 안에 있으므로 `OauthService`가 정규화한 속성을 쓴다(기존 구현 기준).

### 6-14. 프론트 작업 요약
```ts
// 메모리에만 보관
let accessToken: string | null = null;
let refreshing: Promise<string> | null = null;

export function refresh(): Promise<string> {
  // 탭 안 single-flight + 탭 사이 Web Locks
  refreshing ??= navigator.locks.request('token-refresh', async () => {
    const res = await fetch('/api/users/refresh', { method: 'POST', credentials: 'include' });
    if (!res.ok) { accessToken = null; throw new Error('REFRESH_FAILED'); }
    accessToken = (await res.json()).data.accessToken;
    return accessToken!;
  }).finally(() => { refreshing = null; });
  return refreshing;
}
// /oauth/callback 페이지: await refresh(); navigate('/')
// 앱 시작(새로고침): await refresh().catch(() => navigate('/login'))
// 401 TOKEN_EXPIRED 응답: refresh() 후 원 요청 1회 재시도
```
> 탭 사이 잠금 안에서 다른 탭이 이미 새 토큰을 받았을 수 있다. 엄격하게 하려면 잠금 획득 후 `BroadcastChannel`로 받은 최신 Access가 있으면 refresh를 건너뛴다.

## 7. 보안 체크

| 위협 | 대응 |
|---|---|
| XSS로 Refresh 탈취 | HttpOnly 쿠키, JS 접근 불가 |
| XSS로 Access 탈취 | 메모리 보관 + 30분 수명. CSP 적용 권장 |
| CSRF로 `/refresh` 호출 | SameSite=Strict + 응답은 CORS로 공격자가 못 읽음 |
| RT 탈취 후 재사용 | RTR + 재사용 탐지 → Family 폐기 |
| Redis 덤프 유출 | RT 원문 대신 SHA-256만 저장 |
| fid를 아는 공격자의 강제 로그아웃 | 존재하지 않는 RT로는 Family를 건드리지 않음 |
| URL/로그로 토큰 유출 | OAuth 리다이렉트에서 토큰 제거, `no-referrer`, `no-store` |
| Redis 장애 | fail-closed(503). Redis 재기동 시 AOF(`--appendonly yes`)로 Family 유지 |
| 탈퇴·정지 사용자 | refresh 시 `userService.getById`에서 상태 확인, 정지 시 `logoutAll` 호출 |

```
Describe_RefreshTokenService_rotate는

  Context_절대_만료를_지난_경우        └ It_EXPIRED를_반환한다()
  Context_같은_RT로_동시에_두_번_요청한_경우 └ It_하나만_OK이고_하나는_REUSED다()

  Context_Redis가_장애인_경우          └ It_503_AUTH_STORE_UNAVAILABLE을_반환한다()

Describe_AuthController_logout은
  Context_토큰이_없는_경우             └ It_200과_쿠키_삭제_헤더를_반환한다()

  Context_밀려난_기기의_Access로_요청한_경우 └ It_401_SESSION_REPLACED를_반환한다()
```
