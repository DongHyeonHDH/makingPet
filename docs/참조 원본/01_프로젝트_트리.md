# 01. 프로젝트 트리 구조 (템플릿)

> 플레이스홀더: `{{PROJECT_NAME}}`(kebab-case), `{{BASE_PACKAGE}}`(예: `io.myname.myapp`), `{{BASE_PATH}}`(= 패키지를 `/`로 바꾼 경로), `{domain}`(도메인 이름, 소문자 단수).

## 2. 백엔드 패키지 구조 (`src/main/java/{{BASE_PATH}}/`)

```
{{BASE_PACKAGE}}
├─ {{AppName}}Application.java
│
├─ common/                            ─── 공용 인프라 (도메인 로직 금지)
│  ├─ BaseEntity.java                 # createdAt / updatedAt / deletedAt (JPA Auditing)
│  ├─ config/
│  │   ├─ SecurityConfig.java         # FilterChain + CORS + EndPoints 화이트리스트
│  │   ├─ PasswordEncoderConfig.java  # BCrypt
│  │   ├─ JpaConfig.java              # @EnableJpaAuditing
│  │   ├─ QueryDslConfiguration.java  # JPAQueryFactory 빈
│  │   ├─ RedisConfiguration.java     # Lettuce + Redisson
│  │   ├─ S3Config.java               # S3Client + S3Presigner
│  │   ├─ SwaggerConfig.java          # OpenAPI + 도메인별 GroupedOpenApi
│  │   ├─ AdminBootstrapRunner.java   # 최초 관리자 계정 시드
│  │   └─ DataInitConfig.java         # (선택) 개발용 시드
│  ├─ constants/
│  │   ├─ ErrorCode.java              # enum(HttpStatus, description)
│  │   ├─ SuccessCode.java            # enum(successMessage)
│  │   └─ TokenType.java
│  ├─ dto/
│  │   ├─ ApiResponse.java            # 모든 응답 래퍼
│  │   └─ PageResponse.java           # 페이지네이션 래퍼 (권장)
│  ├─ exception/
│  │   └─ BusinessException.java      # ErrorCode 보유 RuntimeException
│  ├─ eventhandler/
│  │   ├─ GlobalExceptionHandler.java # @RestControllerAdvice
│  │   └─ OauthSuccessHandler.java    # OAuth 로그인 성공 → JWT 발급/리다이렉트
│  ├─ filter/
│  │   └─ JwtFilter.java              # OncePerRequestFilter
│  ├─ properties/
│  │   ├─ JwtProperties.java          # @ConfigurationProperties("custom.jwt")
│  │   └─ RedisProperties.java        # @ConfigurationProperties("custom.redis")
│  ├─ security/
│  │   ├─ domain/RefreshToken.java    # Redis 저장 엔티티
│  │   ├─ repository/RefreshTokenRepository.java
│  │   └─ service/
│  │       ├─ TokenProvider.java      # 발급/검증/파싱
│  │       └─ OauthService.java       # OAuth2UserService
│  └─ util/
│      └─ PreConditions.java          # validate(boolean, ErrorCode)
│
├─ user/                              ─── 인증 / 회원 도메인 (거의 모든 프로젝트 공통)
│  ├─ constants/                      # Role, Provider 등 enum
│  ├─ controller/  UserController, AdminUserController
│  ├─ service/     UserService
│  ├─ repository/  UserRepository (+ QueryDSL Custom/Impl)
│  ├─ domain/      User, CurrentUser(UserDetails 구현)
│  └─ dto/         SignupRequest, LoginRequest, LoginResponse, RefreshResponse ...
│
└─ {domain}/                          ─── 도메인 하나 = 아래 5폴더 고정
   ├─ controller/
   │   ├─ {Domain}Controller.java
   │   └─ Admin{Domain}Controller.java   # /api/admin/{domain}s/** (필요 시)
   ├─ service/
   │   └─ {Domain}Service.java
   ├─ repository/
   │   ├─ {Domain}Repository.java
   │   ├─ {Domain}RepositoryCustom.java  # (QueryDSL 필요 시)
   │   └─ {Domain}RepositoryImpl.java
   ├─ domain/
   │   ├─ {Domain}.java                  # extends BaseEntity
   │   └─ {Domain}Status.java            # 상태 enum (필요 시)
   └─ dto/
       ├─ {Domain}CreateRequest.java
       ├─ {Domain}UpdateRequest.java
       ├─ {Domain}Response.java
       └─ {Domain}SummaryResponse.java   # 목록용
```

### 원본에서 쓴 도메인 예시 (참고용)
`user`, `file`(통합 파일: S3 저장/검증/키 생성), `post`, `request`(상태 흐름), `comment`, `category`(3단 트리 + Seeder), `tag`(M:N), `message`(DM + WebSocket broker), `feedback`.

> 파일 업로드가 있는 프로젝트라면 `file/` 도메인을 따로 두고 **저장/검증/메타데이터는 File 서비스에 위임**합니다(`FileService`, `FileValidator`, `S3FileStorageService`, `S3FileKeyGenerator`, `StoragePurgeService`). 다른 도메인은 `fileId(Long)`만 보관합니다.

## 3. 테스트 트리 (`src/test/java/{{BASE_PATH}}/`)

```
├─ {{AppName}}ApplicationTests.java         # contextLoads
├─ util/                                    # 테스트 픽스처 팩토리
│   ├─ TestUtil.java
│   └─ {Domain}Util.java                    # UserUtil, PostUtil ...
└─ {domain}/
    ├─ controller/{Domain}ControllerTests.java   # @WebMvcTest 슬라이스
    ├─ service/{Domain}ServiceTests.java         # Mockito 단위 (@ExtendWith(MockitoExtension))
    ├─ repository/{Domain}RepositoryTests.java   # @DataJpaTest
    ├─ domain/{Domain}Tests.java                 # 엔티티 상태 전이 단위
    └─ integration/{Scenario}IntegrationTest.java# @SpringBootTest 시나리오
```

**테스트 네이밍 (BDD, `@Nested` + `@DisplayName`)**
```
Describe_{대상}_{메서드}는
  └ Context_{조건}_경우
       └ It_{기대결과}()
```

## 4. 의존성/경계 규칙 (반드시 지킴)

1. 다른 도메인의 `domain/`이나 `repository/`를 직접 import하지 않는다. 필요한 경우 **ID(Long)만 보관하고 상대 도메인의 `service`를 호출**한다.
   - 예외: `User` 엔티티는 거의 모든 도메인이 참조하므로 import를 허용한다. 단, 응답 DTO에는 노출하지 않는다.
2. `controller`에서 `repository`를 직접 호출하지 않는다. 반드시 `service`를 거친다.
3. `common/`에는 도메인 로직을 넣지 않는다. 보안, 예외, 응답, 설정만 둔다.
4. 도메인 폴더는 비어 있더라도 5개를 모두 만든다.
5. 새 도메인을 추가할 때는 먼저 `기획/`에 반영하고 그 다음 코드를 작성한다.
6. 런타임 생성물(`data/`, `uploads/`, `*.log`)은 gitignore와 dockerignore에 넣는다.

## 5. 네이밍 컨벤션 요약

| 종류 | 규칙 | 예 |
|---|---|---|
| Entity | 단수 명사 | `Post`, `Message` |
| Repository | `{Entity}Repository` | `PostRepository` |
| Service | `{Domain}Service` | `PostService`, `RequestStatusService` |
| Controller | `{Domain}Controller` / `Admin{Domain}Controller` | |
| Request DTO | `{Entity}{Action}Request` | `PostCreateRequest` |
| Response DTO | `{Entity}Response`, `{Entity}SummaryResponse` | |
| Enum | UpperCamel, 값은 UPPER_SNAKE | `RequestStatus.IN_PROGRESS` |
| DB | snake_case | `linked_request_id` |
| 에러 코드 | `DOMAIN_SUBJECT_REASON` | `POST_NOT_FOUND` |
| 서비스 메서드 동사 | 조회 `get/find/list/search`, 변경 `create/update/softDelete/changeStatus`, 위임 `attach/send` | |
| 변수 | 결과 변수는 과거분사형 | `foundUser`, `savedPost` |

언어 정책: 주석, 에러 메시지, 커밋, PR은 한국어로 쓰고 식별자는 영어로 쓴다.
