# 02. 게임 시스템 규칙

> ⚠️ 2026-11-16 결정 반영: §1-5 중복 펫은 코인 환급(안 B)으로 확정. 본 박스가 최신이며, 본문과 충돌하면 박스를 우선한다.
> 비유: 이 문서는 **"게임의 법전"** 이다. 수치는 모두 `game_config`(또는 설정 테이블)로 빼서 코드 수정 없이 조정할 수 있게 한다.
> 모든 수치는 **초기 제안값**이며 플레이 테스트 후 조정한다. 조정 시 이 문서의 수치를 먼저 바꾼다.

---

## 0. 공통 원칙
1. **서버 권위**: 뽑기·미니게임 결과, 쿨다운, 일일 한도는 서버에서 판정한다. 클라이언트가 보낸 결과값은 받지 않는다.
2. **난수**: `java.security.SecureRandom`을 쓴다. 결과는 기록 테이블에 남긴다.
3. **하루의 기준**: `Asia/Seoul` 자정(00:00 KST)에 일일 한도가 초기화된다.
4. **원자성**: "코인 차감 + 결과 지급"은 반드시 같은 트랜잭션에서 처리한다. 하나라도 실패하면 전부 롤백한다.
5. **중복 방지**: 일일 보상은 `(member_id, 날짜, 종류)` 유니크 제약으로 막는다. 뽑기·구매는 멱등 키 도입 여부를 API 단계에서 정한다.

## 1. 뽑기 (Gacha)

### 1-1. 희귀도와 기본 확률 (상시 풀)
| 희귀도 | 확률 | 예시 |
|---|---|---|
| COMMON | 60% | 기본 오리, 기본 강아지 |
| RARE | 28% | |
| EPIC | 10% | |
| LEGENDARY | 2% | |

- 같은 희귀도 안의 종들은 **균등 확률**로 나눈다(예: RARE 종이 4마리면 각 7%).
- 확률표는 `GET /gacha/pools` 응답으로 **종 단위까지 공개**한다.

### 1-2. 가격
| 종류 | 가격 |
|---|---|
| 1회 | 100 코인 |
| 10연 | 900 코인 (10% 할인) + **RARE 이상 1회 보장** |

### 1-3. 기간 한정 풀 (SHOULD)
- 시작·종료 시각이 있는 풀. 특정 종의 확률을 올린다(픽업).
- 운영 중인 풀의 확률은 수정하지 않는다. 바꿔야 하면 새 풀을 만든다(기록 추적을 위해).

### 1-4. 천장 (SHOULD, M2)
- 풀마다 유저별 카운터를 둔다. **50회 연속 EPIC 이상이 안 나오면 51번째는 EPIC 이상 확정**.
- EPIC 이상이 나오면 카운터를 0으로 되돌린다.

### 1-5. 중복 처리 — ✅ 확정 (G-05, 결정 D-8)
- **이미 보유한 종이 나오면 펫을 주지 않고 코인으로 환급한다.** 유저는 종당 펫 1마리만 가진다.
- 환급 코인: COMMON 20 / RARE 50 / EPIC 150 / LEGENDARY 500.
- 뽑기 응답은 회차마다 `resultType`(NEW_PET / REFUND)과 환급액을 담아, 클라이언트가 "새 친구" 연출과 "이미 있는 친구 → 코인" 연출을 구분할 수 있게 한다.
- 10연 뽑기 안에서 같은 종이 두 번 나오면 첫 번째는 새 펫, 두 번째는 환급으로 처리한다.
- 환급은 뽑기와 같은 트랜잭션에서 원장(`GACHA_REFUND`)에 기록한다.
- 도감을 모두 채운 유저에게는 뽑기 동기가 약해지므로, 한정 풀(1-3)과 v1.1 진화로 보완한다.

### 1-6. 뽑기 기록
- 매 회 결과(풀·희귀도·종·천장 발동 여부·사용 코인)를 남긴다. 확률 검증과 CS 대응에 쓴다.

## 2. 펫 상호작용

### 2-1. 상호작용 종류
| 종류 | 쿨다운 | 기분 | 친밀도 | 재생 움직임 |
|---|---|---|---|---|
| PET (쓰다듬기) | 1분 | +5 | +1 | `motion.pet` |
| PLAY (놀아주기) | 10분 | +15 | +3 | `motion.play` |
| SNACK (간식 주기) | 1시간 | +25 | +5 | `motion.eat` |

- 쿨다운은 **펫별·종류별**로 계산한다.
- 쿨다운 중이면 409(또는 429) + 남은 시간을 응답한다. 코드명은 API 단계에서 정한다.
- 간식은 MVP에서 무료로 둔다. v1.1에서 열매와 합칠 수 있다.

### 2-2. 기분 (Mood, 0~100)
- 시간이 지나면 **1시간에 -2**씩 줄어든다. 최저 0.
- 스케줄러로 깎지 않고, 조회할 때 `마지막 갱신 시각`과 현재 시각으로 **지연 계산(lazy)** 한다.
- 기분 구간에 따라 마이 홈에서 표정·말풍선이 달라진다: 0~29 시무룩 / 30~69 보통 / 70~100 신남.

### 2-3. 친밀도 (Affection) 단계
| 단계 | 누적 친밀도 | 보상 |
|---|---|---|
| 1 | 0 | 기본 움직임 (모든 종 공통 `idle`) |
| 2 | 30 | 종별 해금 움직임 1 |
| 3 | 100 | 종별 해금 움직임 2 + 50 코인 |
| 4 | 250 | 종별 해금 움직임 3 |
| 5 | 500 | 종별 특수 움직임 + 200 코인 |

- 단계가 오르면 해당 **움직임 아이템이 인벤토리에 지급**되고, 그 종의 모든 펫이 쓸 수 있다.
- 움직임은 **거래할 수 없다**.

## 3. 꾸미기 (마이 홈)

### 3-1. 장착 슬롯
| 슬롯 | 아이템 카테고리 | 펫당 개수 |
|---|---|---|
| TOP | 상의 | 1 |
| BOTTOM | 하의 | 1 |
| ACCESSORY | 악세서리 | 2 (머리·몸 구분은 v1.1) |
| MOTION | 움직임 | 1 (대표 움직임) |

- 시안에 있던 "신발"은 MVP에서 `ACCESSORY`에 포함한다. 슬롯을 따로 만들지는 API 단계에서 확정한다.
- 아이템은 **수량형**이다. 같은 아이템 3개를 가지면 펫 3마리에게 하나씩 입힐 수 있다.
- **거래 가능 수량 = 보유 수량 − 장착 중 수량 − 배치 중 수량 − 경매 등록 중 수량**. 장착·배치 중인 아이템은 경매에 올릴 수 없다.
- 일부 종 전용 아이템을 허용할지는 v1.1에서 정한다 (MVP는 모든 종 공용).

### 3-2. 방 꾸미기
- **테마**: 벽지+바닥 묶음 1개 적용. 기본 테마 1종을 가입 시 지급.
- **가구**: 방 좌표(0~100 비율 좌표) + 레이어 순서로 배치. **최대 20개**.
- 공개 설정(PUBLIC/PRIVATE). 기본값은 PUBLIC.

## 4. 재화 (코인)

### 4-1. 획득처 (Source)
| 획득처 | 보상 | 한도 |
|---|---|---|
| 가입 선물 | 300 코인 (1회 뽑기 3번) | 1회 |
| 출석 | 30 코인, 연속 7일째 +100 보너스 | 1일 1회 |
| 가위바위보 | 승 50 / 무 20 / 패 10 | 1일 1회 |
| 빠칭코(슬롯) | §5-3 배당표 | 1일 5회 |
| 친밀도 단계 보상 | §2-3 | 단계별 1회 |
| 중복 펫 환급 | §1-5 | |
| 경매장 판매 대금 | 판매가 − 수수료 | |

### 4-2. 소모처 (Sink) — 인플레이션 방지
| 소모처 | 금액 |
|---|---|
| 뽑기 | 100 / 900 |
| 상점 구매 | 상품가 |
| 빠칭코 참가비 | 20 코인/회 |
| **경매장 판매 수수료** | 판매가의 5% (올림, 최소 1) |

- 경매장 거래 자체는 유저 사이에서 코인을 옮길 뿐이라 총량이 바뀌지 않는다. 수수료만 총량을 줄인다.
- 일일 획득 기대치(출석+가위바위보+슬롯): 약 **80~130 코인/일** → 하루 약 1회 뽑기. 밸런스 기준점으로 삼는다.

### 4-3. 원장 규칙
- 잔액은 `wallets.balance` 한 곳에만 두고, 바꿀 때마다 `coin_transactions`에 (금액, 바뀐 뒤 잔액, 사유, 참조 ID)를 남긴다.
- 차감은 **조건부 UPDATE**(`balance >= :amount`)로 처리한다. 영향받은 행이 0이면 잔액 부족 에러.
- 잔액은 음수가 될 수 없다(DB `CHECK (balance >= 0)`).

## 5. 미니게임

### 5-1. 출석
- 하루 1회. 어제 출석했으면 연속일 +1, 아니면 1로 초기화.
- 연속 7일째에 보너스를 주고 다음 날 1일차로 순환한다.

### 5-2. 가위바위보
- 하루 1회. 유저가 손(ROCK/PAPER/SCISSORS)을 보내면 서버가 상대 손을 무작위로 정하고 결과를 판정해 기록·보상을 한 번에 처리한다.
- 응답: 내 손, 상대 손, 결과, 보상, 오늘 남은 횟수.

### 5-3. 빠칭코 (슬롯)
- 하루 5회, 회당 참가비 20 코인. 서버가 3칸의 심볼을 결정한다.
- 심볼: 🐥 오리, 🐱 고양이, 🐶 강아지, 🦖 공룡, 🍓 딸기, ⭐ 별

| 결과 | 확률(제안) | 배당 |
|---|---|---|
| ⭐⭐⭐ | 1% | 500 |
| 같은 펫 3개 | 4% | 150 |
| 🍓🍓🍓 | 5% | 80 |
| 아무거나 2개 같음 | 30% | 30 |
| 꽝 | 60% | 0 |

- 기대 배당 ≈ 0.01×500 + 0.04×150 + 0.05×80 + 0.30×30 = **24 코인/회** (참가비 20 → 회당 기대 +4). 무과금 게임이라 "약간 이득"으로 두어 참여 동기를 만든다.
- 구현은 **결과 등급을 먼저 확률로 뽑고, 그 등급에 맞는 심볼 배치를 만든다**. 심볼을 독립으로 굴리면 확률표를 맞추기 어렵다.
- 결과 화면 연출(릴 회전)은 클라이언트가 하되, 멈출 위치는 서버 응답값으로만 정한다.
- 법적 메모: 유료 재화·현금 환전이 없으므로 사행성 문제는 작지만, 코인의 현금 거래(외부 RMT)는 이용약관으로 금지한다.

## 6. 상점
- 운영자가 등록한 상품을 고정가로 판다. 재고는 무한.
- 상품 = (아이템, 가격, 판매 기간, 노출 여부). 기간 한정 상품을 둘 수 있다.

## 7. 경매장

### 7-1. 방식 — MVP는 "즉시구매형 거래소"
- 시안(`web-preview/market.js`)과 같이 **판매자가 정한 가격에 바로 사는 방식**을 MVP로 한다.
- 입찰식 경매(A-10)는 M3 COULD. 입찰식은 실시간 갱신이 필요해 프로토콜 명세 범위가 커진다.

### 7-2. 거래 대상
| 대상 | 거래 |
|---|---|
| 의상 (상의·하의·악세서리) | 가능 |
| 가구·테마 | 가능 |
| 움직임 | 불가 (친밀도 보상) |
| 펫 | 불가 (MVP) |
| 이벤트 한정 아이템 | 아이템별 `tradable` 플래그로 결정 |

### 7-3. 등록 규칙
| 항목 | 값 |
|---|---|
| 1건당 수량 | 1개 (MVP). 묶음 판매는 v1.1 |
| 가격 범위 | 1 ~ 99,999 코인 |
| 등록 기간 | 12 / 24 / 48 시간 중 선택 |
| 동시 등록 한도 | 유저당 10건 |
| 등록 수수료 | 없음 |
| 판매 수수료 | 판매가의 5% (올림, 최소 1) — 판매 대금에서 차감 |

### 7-4. 매물 상태
```
ON_SALE(판매 중) ──구매──▶ SOLD(판매 완료)
     │
     ├──판매자 취소──▶ CANCELLED(취소)    → 아이템 판매자에게 반환
     ├──기간 만료───▶ EXPIRED(만료)      → 아이템 판매자에게 반환
     └──관리자 내림──▶ REMOVED(운영 조치) → 아이템 판매자에게 반환
```
- 상태 전이는 `ON_SALE`에서만 가능하다. 다른 상태로 간 매물은 더 바뀌지 않는다.

### 7-5. 구매 처리 (한 트랜잭션)
1. 매물 행을 잠그고(`FOR UPDATE`) 상태가 `ON_SALE`이며 만료 전인지 확인한다.
2. 구매자 ≠ 판매자인지 확인한다.
3. 구매자 코인을 조건부 UPDATE로 차감한다.
4. 판매자에게 (판매가 − 수수료)를 지급한다.
5. 구매자 인벤토리에 아이템 1개를 더한다.
6. 매물을 `SOLD`로 바꾸고 거래 기록(`auction_trades`)을 남긴다.
7. 원장에 구매자 차감·판매자 입금·수수료를 기록한다.

- 동시에 두 명이 사면 1명만 성공하고 나머지는 "이미 판매된 매물"(409)을 받는다.
- **데드락 방지**: 매물 → 지갑 순서로 잠그고, 두 지갑은 member_id 오름차순으로 잠근다.

### 7-6. 만료 처리
- 1분 주기 스케줄러가 `ON_SALE`이면서 만료 시각이 지난 매물을 `EXPIRED`로 바꾸고 아이템을 돌려준다.
- 조회 시점에는 만료 시각을 기준으로 "만료됨"으로 보이게 필터링해, 스케줄러가 늦어도 사용자는 만료 매물을 살 수 없게 한다.

### 7-7. 시세
- 아이템별 **현재 최저 매물가**와 **최근 7일 체결가 평균·건수**를 보여준다.
- 시안의 "시세" 탭에 해당한다.

## 8. v1.1 진화 (설계만 열어둠)
- 종마다 진화 단계(1→2→…→5 이상)를 둔다. 단계마다 이미지·필요 재료(열매 종류·개수)·필요 친밀도 단계.
- 열매는 아이템 카테고리 `FRUIT`로 추가하고, 출석·가위바위보·슬롯 보상 테이블에서 일정 확률로 지급한다.
- 이를 위해 MVP부터 `user_pets`에 `stage`(기본 1) 컬럼을 두고, 보상 지급 로직은 "코인 금액"이 아니라 "보상 항목 목록"을 돌려주게 만든다.
