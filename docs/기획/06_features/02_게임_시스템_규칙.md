# 02. 게임 시스템 규칙

> ⚠️ 2026-11-16 결정 반영: §1-5 중복 펫은 코인 환급(안 B)으로 확정. 본 박스가 최신이며, 본문과 충돌하면 박스를 우선한다.
> ⚠️ 2026-11-18 결정 반영(D-14): 진화는 **속성 열매** 방식이다. 속성 4개(불·물·풀·번개), 속성 수가 희귀도(0 COMMON ~ 3 LEGENDARY), 첫 속성이 주속성, 4계열 × 29형태 = 116형태. §8을 다시 썼다.
> ⚠️ 2026-11-18 결정 반영(D-13, 같은 날 진화 M2 편입): 펫은 **4계열 × 4단계 = 16종**(→ D-14로 4계열 × 29형태 = 116형태로 바뀜). 뽑기는 기본종(COMMON) 4종만, 진화형(RARE~LEGENDARY)은 **진화로만** 얻는다. §1-1·1-2·1-4·1-5·§8이 바뀌었다.
> 비유: 이 문서는 **"게임의 법전"** 이다. 수치는 모두 `game_config`(또는 설정 테이블)로 빼서 코드 수정 없이 조정할 수 있게 한다.
> 모든 수치는 **초기 제안값**이며 플레이 테스트 후 조정한다. 조정 시 이 문서의 수치를 먼저 바꾼다.

## 0. 공통 원칙
1. **서버 권위**: 뽑기·미니게임 결과, 쿨다운, 일일 한도는 서버에서 판정한다. 클라이언트가 보낸 결과값은 받지 않는다.
2. **난수**: `java.security.SecureRandom`을 쓴다. 결과는 기록 테이블에 남긴다.
3. **하루의 기준**: `Asia/Seoul` 자정(00:00 KST)에 일일 한도가 초기화된다.
4. **원자성**: "코인 차감 + 결과 지급"은 반드시 같은 트랜잭션에서 처리한다. 하나라도 실패하면 전부 롤백한다.
5. **중복 방지**: 일일 보상은 `(member_id, 날짜, 종류)` 유니크 제약으로 막는다. 뽑기·구매는 멱등 키 도입 여부를 API 단계에서 정한다.

## 1. 뽑기 (Gacha)

### 1-1. 뽑기 대상과 확률 (상시 풀) — D-13
- 뽑기에서는 **기본종(1단계, COMMON) 4종만** 나온다: 오리·강아지·고양이·공룡.
- 진화형(RARE·EPIC·LEGENDARY)은 뽑기에서 나오지 않는다. **진화(§8)로만** 얻는다.

| 희귀도 | 뽑기 확률 | 얻는 방법 |
|---|---|---|
| COMMON | 100% (4종 × 각 25%) | 뽑기 |
| RARE | 0% | 속성 1개를 얻는 진화 (§8, D-14) |
| EPIC | 0% | 속성 2개 |
| LEGENDARY | 0% | 속성 3개 |

- 기본종은 **균등 확률**로 나눈다. 기본종이 늘어나도 균등 분배를 기본으로 한다.
- 확률표는 `GET /gacha/pools` 응답으로 **종 단위까지 공개**한다.

### 1-2. 가격
| 종류 | 가격 |
|---|---|
| 1회 | 100 코인 |
| 10연 | 900 코인 (10% 할인). RARE 이상 1회 보장은 D-13으로 폐지 (뽑기에 RARE가 없다) |

### 1-3. 기간 한정 풀 (SHOULD)
- 시작·종료 시각이 있는 풀. 특정 종의 확률을 올린다(픽업). 픽업 대상도 기본종이다(D-13).
- 운영 중인 풀의 확률은 수정하지 않는다. 바꿔야 하면 새 풀을 만든다(기록 추적을 위해).

### 1-4. 천장 — 폐지 (D-13)
- 뽑기 결과가 모두 COMMON이라 "EPIC 이상 확정" 천장은 의미가 없다. 폐지한다.
- `gacha_pools.pity_threshold`, `gacha_pity_counters`, G-4 API는 코드 정리 때 제거하거나 쓰지 않는다.
- 도감을 채운 뒤의 뽑기 동기는 "진화시킨 기본종을 다시 뽑는 것"(§8-4)에서 나온다.

### 1-5. 중복 처리 — ✅ 확정 (G-05, 결정 D-8)
- **이미 보유한 종이 나오면 펫을 주지 않고 코인으로 환급한다.** 유저는 종당 펫 1마리만 가진다.
- 환급 코인: **20** (뽑기에서는 COMMON만 나온다, D-13). 이전 표의 RARE 50 / EPIC 150 / LEGENDARY 500은 쓰지 않는다.
- 뽑기 응답은 회차마다 `resultType`(NEW_PET / REFUND)과 환급액을 담아, 클라이언트가 "새 친구" 연출과 "이미 있는 친구 → 코인" 연출을 구분할 수 있게 한다.
- 10연 뽑기 안에서 같은 종이 두 번 나오면 첫 번째는 새 펫, 두 번째는 환급으로 처리한다.
- 환급은 뽑기와 같은 트랜잭션에서 원장(`GACHA_REFUND`)에 기록한다.
- 중복은 *지금 보유 중인* 종 기준이다. 기본종을 진화시키면 그 기본종은 다시 뽑을 수 있다(§8-4).

### 1-6. 뽑기 기록
- 매 회 결과(풀·희귀도·종·천장 발동 여부·사용 코인)를 남긴다. 확률 검증과 CS 대응에 쓴다.

## 2. 펫 상호작용

### 2-1. 상호작용 종류
| 종류 | 쿨다운 | 기분 | 친밀도 | 재생 움직임 |
|---|---|---|---|---|
| PET (쓰다듬기) | 1분 | +5 | +1 | `motion.pet` |
| PLAY (놀아주기) | 10분 | +15 | +3 | `motion.play` |
| SNACK (간식 주기) | 1시간 | +25 | +5 | `motion.eat` |

- 쿨다운은 **펫별·종류별**로 계산한다.
- 쿨다운 중이면 409(또는 429) + 남은 시간을 응답한다. 코드명은 API 단계에서 정한다.
- 간식은 MVP에서 무료로 둔다. M2에서 열매와 합칠 수 있다.

### 2-2. 기분 (Mood, 0~100)
- 시간이 지나면 **1시간에 -2**씩 줄어든다. 최저 0.
- 스케줄러로 깎지 않고, 조회할 때 `마지막 갱신 시각`과 현재 시각으로 **지연 계산(lazy)** 한다.
- 기분 구간에 따라 마이 홈에서 표정·말풍선이 달라진다: 0~29 시무룩 / 30~69 보통 / 70~100 신남.

### 2-3. 친밀도 (Affection) 단계
| 단계 | 누적 친밀도 | 보상 |
|---|---|---|
| 1 | 0 | 기본 움직임 (모든 종 공통 `idle`) |
| 2 | 30 | 종별 해금 움직임 1 |
| 3 | 100 | 종별 해금 움직임 2 + 50 코인 |
| 4 | 250 | 종별 해금 움직임 3 |
| 5 | 500 | 종별 특수 움직임 + 200 코인 |

- 단계가 오르면 해당 **움직임 아이템이 인벤토리에 지급**되고, 같은 **움직임 그룹**(§8-4)의 모든 형태가 쓸 수 있다. 이미 가진 움직임은 다시 지급하지 않는다.
- 움직임은 **거래할 수 없다**.

## 3. 꾸미기 (마이 홈)

### 3-1. 장착 슬롯
| 슬롯 | 아이템 카테고리 | 펫당 개수 |
|---|---|---|
| TOP | 상의 | 1 |
| BOTTOM | 하의 | 1 |
| ACCESSORY | 악세서리 | 2 (머리·몸 구분은 v1.1) |
| MOTION | 움직임 | 1 (대표 움직임) |

- 시안에 있던 "신발"은 MVP에서 `ACCESSORY`에 포함한다. 슬롯을 따로 만들지는 API 단계에서 확정한다.
- 아이템은 **수량형**이다. 같은 아이템 3개를 가지면 펫 3마리에게 하나씩 입힐 수 있다.
- **거래 가능 수량 = 보유 수량 − 장착 중 수량 − 배치 중 수량 − 경매 등록 중 수량**. 장착·배치 중인 아이템은 경매에 올릴 수 없다.
- 일부 종 전용 아이템을 허용할지는 v1.1에서 정한다 (MVP는 모든 종 공용).

### 3-2. 방 꾸미기
- **테마**: 벽지+바닥 묶음 1개 적용. 기본 테마 1종을 가입 시 지급.
- **가구**: 방 좌표(0~100 비율 좌표) + 레이어 순서로 배치. **최대 20개**.
- 공개 설정(PUBLIC/PRIVATE). 기본값은 PUBLIC.

## 4. 재화 (코인)

### 4-1. 획득처 (Source)
| 획득처 | 보상 | 한도 |
|---|---|---|
| 가입 선물 | 300 코인 (1회 뽑기 3번) | 1회 |
| 출석 | 30 코인, 연속 7일째 +100 보너스 | 1일 1회 |
| 가위바위보 | 승 50 / 무 20 / 패 10 | 1일 1회 |
| 빠칭코(슬롯) | §5-3 배당표 | 1일 5회 |
| 친밀도 단계 보상 | §2-3 | 단계별 1회 |
| 중복 펫 환급 | §1-5 | |
| 경매장 판매 대금 | 판매가 − 수수료 | |

### 4-2. 소모처 (Sink) — 인플레이션 방지
| 소모처 | 금액 |
|---|---|
| 뽑기 | 100 / 900 |
| 상점 구매 | 상품가 |
| 빠칭코 참가비 | 20 코인/회 |
| **경매장 판매 수수료** | 판매가의 5% (올림, 최소 1) |

- 경매장 거래 자체는 유저 사이에서 코인을 옮길 뿐이라 총량이 바뀌지 않는다. 수수료만 총량을 줄인다.
- 일일 획득 기대치(출석+가위바위보+슬롯): 약 **80~130 코인/일** → 하루 약 1회 뽑기. 밸런스 기준점으로 삼는다.

### 4-3. 원장 규칙
- 잔액은 `wallets.balance` 한 곳에만 두고, 바꿀 때마다 `coin_transactions`에 (금액, 바뀐 뒤 잔액, 사유, 참조 ID)를 남긴다.
- 차감은 **조건부 UPDATE**(`balance >= :amount`)로 처리한다. 영향받은 행이 0이면 잔액 부족 에러.
- 잔액은 음수가 될 수 없다(DB `CHECK (balance >= 0)`).

## 5. 미니게임

### 5-1. 출석
- 하루 1회. 어제 출석했으면 연속일 +1, 아니면 1로 초기화.
- 연속 7일째에 보너스를 주고 다음 날 1일차로 순환한다.

### 5-2. 가위바위보
- 하루 1회. 유저가 손(ROCK/PAPER/SCISSORS)을 보내면 서버가 상대 손을 무작위로 정하고 결과를 판정해 기록·보상을 한 번에 처리한다.
- 응답: 내 손, 상대 손, 결과, 보상, 오늘 남은 횟수.

### 5-3. 빠칭코 (슬롯)
- 하루 5회, 회당 참가비 20 코인. 서버가 3칸의 심볼을 결정한다.
- 심볼: 🐥 오리, 🐱 고양이, 🐶 강아지, 🦖 공룡, 🍓 딸기, ⭐ 별

| 결과 | 확률(제안) | 배당 |
|---|---|---|
| ⭐⭐⭐ | 1% | 500 |
| 같은 펫 3개 | 4% | 150 |
| 🍓🍓🍓 | 5% | 80 |
| 아무거나 2개 같음 | 30% | 30 |
| 꽝 | 60% | 0 |

- 기대 배당 ≈ 0.01×500 + 0.04×150 + 0.05×80 + 0.30×30 = **24 코인/회** (참가비 20 → 회당 기대 +4). 무과금 게임이라 "약간 이득"으로 두어 참여 동기를 만든다.
- 구현은 **결과 등급을 먼저 확률로 뽑고, 그 등급에 맞는 심볼 배치를 만든다**. 심볼을 독립으로 굴리면 확률표를 맞추기 어렵다.
- 결과 화면 연출(릴 회전)은 클라이언트가 하되, 멈출 위치는 서버 응답값으로만 정한다.
- 법적 메모: 유료 재화·현금 환전이 없으므로 사행성 문제는 작지만, 코인의 현금 거래(외부 RMT)는 이용약관으로 금지한다.

## 7. 경매장

### 7-1. 방식 — MVP는 "즉시구매형 거래소"
- 시안(`web-preview/market.js`)과 같이 **판매자가 정한 가격에 바로 사는 방식**을 MVP로 한다.
- 입찰식 경매(A-10)는 M3 COULD. 입찰식은 실시간 갱신이 필요해 프로토콜 명세 범위가 커진다.

### 7-2. 거래 대상
| 대상 | 거래 |
|---|---|
| 의상 (상의·하의·악세서리) | 가능 |
| 가구·테마 | 가능 |
| 열매 | 가능 (D-14). 판매 수수료 5%가 그대로 붙는다 |
| 움직임 | 불가 (친밀도 보상) |
| 펫 | 불가 (MVP) |
| 이벤트 한정 아이템 | 아이템별 `tradable` 플래그로 결정 |

### 7-3. 등록 규칙
| 항목 | 값 |
|---|---|
| 1건당 수량 | 1개. 단, **열매(`FRUIT`)는 1~10개 묶음**으로 등록할 수 있다 (D-14, M2). 다른 카테고리 묶음은 v1.1 |
| 가격 범위 | 1 ~ 99,999 코인. 묶음이면 **묶음 전체 가격** |
| 등록 기간 | 12 / 24 / 48 시간 중 선택 |
| 동시 등록 한도 | 유저당 10건 |
| 등록 수수료 | 없음 |
| 판매 수수료 | 판매가의 5% (올림, 최소 1) — 판매 대금에서 차감. 묶음은 묶음 전체 가격 기준 |

- 묶음은 **통째로만** 산다. 일부만 사는 기능은 없다. 그래서 구매·동시성 처리는 1개짜리 매물과 같다.
- 묶음 매물은 단가(= 가격 ÷ 수량, 소수 첫째 자리 반올림)를 함께 보여준다. 단가는 표시·정렬·시세용이고, 결제는 묶음 가격으로 한다.
- 등록하면 묶음 수량만큼 에스크로로 빠진다. 취소·만료·내림 시 묶음 수량을 그대로 돌려준다.

### 7-4. 매물 상태
```
ON_SALE(판매 중) ──구매──▶ SOLD(판매 완료)
     │
     ├──판매자 취소──▶ CANCELLED(취소)    → 아이템 판매자에게 반환
     ├──기간 만료───▶ EXPIRED(만료)      → 아이템 판매자에게 반환
     └──관리자 내림──▶ REMOVED(운영 조치) → 아이템 판매자에게 반환
```
- 상태 전이는 `ON_SALE`에서만 가능하다. 다른 상태로 간 매물은 더 바뀌지 않는다.

### 7-5. 구매 처리 (한 트랜잭션)
1. 매물 행을 잠그고(`FOR UPDATE`) 상태가 `ON_SALE`이며 만료 전인지 확인한다.
2. 구매자 ≠ 판매자인지 확인한다.
3. 구매자 코인을 조건부 UPDATE로 차감한다.
4. 판매자에게 (판매가 − 수수료)를 지급한다.
5. 구매자 인벤토리에 매물 수량(1개 또는 열매 묶음 수량)만큼 더한다.
6. 매물을 `SOLD`로 바꾸고 거래 기록(`auction_trades`)을 남긴다.
7. 원장에 구매자 차감·판매자 입금·수수료를 기록한다.

- 동시에 두 명이 사면 1명만 성공하고 나머지는 "이미 판매된 매물"(409)을 받는다.
- **데드락 방지**: 매물 → 지갑 순서로 잠그고, 두 지갑은 member_id 오름차순으로 잠근다.

### 7-6. 만료 처리
- 1분 주기 스케줄러가 `ON_SALE`이면서 만료 시각이 지난 매물을 `EXPIRED`로 바꾸고 아이템을 돌려준다.
- 조회 시점에는 만료 시각을 기준으로 "만료됨"으로 보이게 필터링해, 스케줄러가 늦어도 사용자는 만료 매물을 살 수 없게 한다.

### 7-7. 시세
- 아이템별 **현재 최저 매물가**와 **최근 7일 체결가 평균·건수**를 보여준다.
- 열매처럼 묶음이 섞이는 아이템은 **단가 기준**으로 계산한다(최저 단가, 7일 평균 단가, 체결 수량 합계).
- 시안의 "시세" 탭에 해당한다.

## 8. 진화 — 속성 (D-14 · 기능은 M2)
> 2026-11-18 개정(D-14). D-13의 "계열별 고정 진화형 16종"을 **속성 진화**로 바꾼다.
> D-13에서 그대로 남는 것: 4계열, 뽑기는 기본종(COMMON)만, 진화형은 진화로만, 진화는 M2.

### 8-1. 속성과 열매
| 속성 | 코드 | 열매 |
|---|---|---|
| 불 | `FIRE` | 불꽃 열매 `fruit_fire` |
| 물 | `WATER` | 물방울 열매 `fruit_water` |
| 풀 | `GRASS` | 새싹 열매 `fruit_grass` |
| 번개 | `ELECTRIC` | 번개 열매 `fruit_electric` |

- 펫에게 열매를 먹이면 그 열매의 **속성을 얻으며 진화**한다.
- 같은 속성은 한 번만 얻는다. 펫 하나가 가질 수 있는 속성은 **최대 3개**다(4개 모두는 없음).
- 속성은 v3 전투(속성·기술 조합)의 타입으로 그대로 이어진다. 주속성이 대표 타입이다.

### 8-2. 속성 수 = 희귀도
| 속성 수 | 희귀도 | 계열당 형태 수 | 오리 계열 예 |
|---|---|---|---|
| 0 | COMMON | 1 | 오리 |
| 1 | RARE | 4 | 불 오리 |
| 2 | EPIC | 12 (주속성 4 × 부속성 3) | 불 오리 + 물 |
| 3 | LEGENDARY | 12 (주속성 4 × 부속성 조합 3) | 불 오리 + 물·풀 |
| 합계 | | **29** | 4계열 × 29 = **116형태** |

### 8-3. 주속성 규칙
- **처음 얻은 속성이 주속성**이다. 이후 진화해도 바뀌지 않는다.
- 두 번째·세 번째 속성(부속성)은 얻은 순서와 상관없다. 불→물→풀과 불→풀→물은 같은 형태다.
- 주속성이 다르면 다른 형태다. 물→불은 불→물과 다르다.
- 아트 가이드: 주속성이 체형·표정·주요 색을, 부속성이 소품·무늬·이펙트를 정한다. 같은 주속성끼리는 한눈에 같은 갈래로 보이게 한다.

### 8-4. 형태 = 종
- 116형태는 각각 `pet_species` 한 행이다. **형태마다 전용 아트**, 이름, 도감 칸을 가진다. 해금 움직임은 아래 움직임 그룹 단위로 공유한다.
- 코드 규칙: `<계열>` · `<계열>_<주속성>` · `<계열>_<주속성>__<부속성(알파벳순)>` (소문자)
  - 예: `duck`, `duck_fire`, `duck_fire__water`, `duck_fire__grass_water`
- 이름은 아트와 함께 정한다. RARE 가안: 불 오리 = 화난 오리, 풀 고양이 = 들고양이.
- 모든 형태가 "허술한 귀여움"을 유지한다. 오리지널 원칙(개요 문서)을 따르며, 기존 IP의 속성별 형태를 닮게 하지 않는다.

**움직임 그룹 (D-14)**
- 해금 움직임(친밀도 2~5단계 보상)은 **계열·주속성 단위**로 공유한다. 그룹 코드는 그 그룹의 RARE 형태 코드와 같다.

| 그룹 | 속하는 형태 | 수 |
|---|---|---|
| 기본종 그룹 `duck` | 오리 (속성 0개) | 계열 4개 → 4그룹 |
| 계열·주속성 그룹 `duck_fire` | 불 오리(RARE), 불 오리 + 물·풀·번개 중 1개(EPIC 3), + 2개(LEGENDARY 3) | 계열 4 × 주속성 4 → 16그룹 |

- 그룹 20개 × 단계 4개 = **움직임 80개**. 형태마다 따로 만들면 464개다.
- 진화형은 자기 그룹 움직임과 **같은 계열 기본종 그룹 움직임**을 모두 장착할 수 있다.
- 단계 코인 보상(3단계 50, 5단계 200)은 움직임과 달리 형태마다 다시 받는다(§8-6).

### 8-5. 진화 조건 (초기 제안값)
| 진화 | 결과 희귀도 | 필요 친밀도 단계 | 필요 열매 |
|---|---|---|---|
| 속성 0 → 1 | RARE | 3단계 (누적 100) | 고른 속성의 열매 3 |
| 속성 1 → 2 | EPIC | 4단계 (누적 250) | 고른 속성의 열매 5 |
| 속성 2 → 3 | LEGENDARY | 5단계 (누적 500) | 고른 속성의 열매 8 |

- 유저가 어떤 열매를 먹일지 고른다. 이미 가진 속성의 열매는 먹일 수 없다.
- 열매는 아이템 카테고리 `FRUIT`다. 출석·가위바위보·슬롯 보상에서 일정 확률로 지급하고, 속성은 4종 균등 무작위다.
- 열매는 **거래할 수 있고 1~10개 묶음으로 팔 수 있다**(`tradable=true`, §7-3). 필요한 속성 열매를 경매장에서 사고팔 수 있고, 판매 수수료 5%는 재화 회수 장치로도 작동한다. 열매 시세는 §4 인플레이션 감시에 함께 본다.
- 이를 위해 보상 지급 로직은 "코인 금액"이 아니라 "보상 항목 목록"을 돌려주게 만든다(기존 방침 유지).
- 진화는 유저가 직접 실행한다. 조건을 채우면 펫 상세에 속성별 "진화하기"가 열린다.

### 8-6. 진화할 때 바뀌는 것 (한 트랜잭션)
| 항목 | 처리 |
|---|---|
| 종 | `user_pets.species_id`를 (같은 계열, 같은 주속성, 부속성 + 새 속성) 형태로 바꾼다. 첫 진화면 새 속성이 주속성 |
| 열매 | 인벤토리에서 차감한다. 조건부 UPDATE, 부족하면 전체 실패 |
| 친밀도 | 0, 단계 1로 초기화한다. 단계를 다시 올리며 새 그룹의 움직임을 모은다. 같은 그룹 안에서 진화했다면 이미 받은 움직임은 다시 주지 않는다 |
| 기분·이름·장착 아이템·대표 펫 여부 | 유지 |
| 이미 받은 움직임 아이템 | 인벤토리에 남는다 |
| 기록 | `pet_evolutions`에 (펫, 이전 종, 다음 종, 얻은 속성, 사용 열매·개수, 시각) |

- 친밀도 초기화로 3·5단계 코인 보상(50·200)은 형태마다 다시 받는다. 한 펫이 3번 진화하면 최대 1,000코인이다. §4 인플레이션 감시 대상에 넣는다.

### 8-7. 보유 규칙과 도감
- **종당 1마리**(D-8)는 **형태당 1마리**가 된다. 중복 판정은 *지금 보유 중인* 형태 기준이다.
- 결과 형태를 이미 가지고 있으면 그 속성으로는 진화할 수 없다.
- 진화하면 이전 형태 칸이 비므로, 기본종은 뽑기로 다시 얻을 수 있다. 이것이 계속 뽑기를 하는 이유다.
- 펫 한 마리는 형태 하나에서 멈추므로, 한 계열 29형태를 모두 가지려면 기본종을 29번 얻어야 한다. 도감 완성은 장기 목표다.
- 도감은 116칸이다. 계열 → 주속성 순으로 묶어 보여준다. 미보유는 실루엣과 "<이전 형태> + <속성> 열매" 힌트를 보여준다.
