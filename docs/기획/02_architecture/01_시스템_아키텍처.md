> ⚠️ 2026-11-16 초안. 본 박스가 최신이며, 본문과 충돌하면 박스를 우선한다.

## 레이어 규칙
`controller → service → repository` 단방향. controller는 repository를 호출하지 않는다. 트랜잭션 경계는 service.

## 패키지 구조 (현재 코드 기준 `com.gorapaduk.makingpet`)
```
com.gorapaduk.makingpet
├─ common/        config, constants(ErrorCode), dto(응답 래퍼·PageResponse), exception, util
├─ auth/          ← 현재 코드. member 도메인으로 이름을 바꿀지 결정 D-6
├─ pet/  gacha/  item/  home/  wallet/  reward/  shop/  auction/  community/  admin/
│   └─ 각 도메인: controller / service / repository / domain / dto
```
> 현재 `auth`는 `model/dto`, `model/entity` 구조다. 참조 원본은 `domain / dto` 5폴더 규칙이다. 새 도메인부터 5폴더 규칙을 적용하고 `auth`는 M1 중에 맞춘다(제안).

## 도메인 간 호출 규칙
| 호출자 | 피호출 | 용도 |
|---|---|---|
| gacha | wallet, pet | 코인 차감, 펫 생성 |
| pet | item | 친밀도 단계 보상(움직임) 지급 |
| pet, home | item | 장착·배치 시 수량 예약·해제 |
| reward | wallet | 보상 지급, 슬롯 참가비 차감 |
| shop | wallet, item | 구매 |
| auction | wallet, item | 에스크로, 정산 |
| member | wallet, home | 가입 시 지갑·기본 마이 홈 생성 |

- 다른 도메인의 엔티티·리포지토리를 직접 import하지 않는다. ID(UUID)만 보관한다.
- **wallet과 item은 "원자적 연산" 메서드만 노출한다**: `wallet.debit(memberId, amount, reason, refId)`, `wallet.credit(...)`, `item.grant(...)`, `item.reserve(...)`, `item.release(...)`. 호출자 트랜잭션에 참여한다(`Propagation.REQUIRED`).

## 동시성·정합성 설계
| 상황 | 방식 |
|---|---|
| 코인 차감 | 조건부 UPDATE `balance = balance - :a WHERE member_id = :m AND balance >= :a` |
| 출석·가위바위보 중복 | `(member_id, reward_date, type)` 유니크 제약. 위반 시 "이미 참여" 에러 |
| 슬롯 일일 횟수 | `daily_counters(member_id, date, type, count)` 행을 잠그고 증가 |
| 경매 동시 구매 | 매물 행 `SELECT ... FOR UPDATE` + 상태 확인. 잠금 순서: 매물 → 지갑(member_id 오름차순) |
| 상호작용 쿨다운 | `pet_interaction_cooldowns` 행 잠금 또는 조건부 UPDATE `WHERE next_available_at <= now` |
| 매물 만료 | 스케줄러 + 조회·구매 시 만료 시각 재검증 |

> Redis/Redisson 분산락은 서버를 여러 대로 늘릴 때 검토한다. 단일 인스턴스 + DB 락으로 시작한다.

## 인증 흐름 (현재 구현)
1. `POST /api/v1/auth/login` → HS256 Access Token(30분, `sub` = member UUID, `iss` = makingpet) 발급.
2. 이후 요청은 `Authorization: Bearer <token>`. Spring Security OAuth2 Resource Server가 검증한다.
3. Refresh Token·로그아웃은 M2 (결정 D-5).
4. Role 클레임은 아직 없다. 관리자 API 도입 시 `role` 클레임과 `members.role` 컬럼을 추가한다.

## 에셋(이미지·움직임) 흐름
- 펫·아이템 이미지는 **운영자만 등록**한다. 유저 업로드 엔드포인트는 만들지 않는다.
- API는 이미지 바이트가 아니라 **에셋 키**(`pets/duck/base.png`)를 돌려주고, 클라이언트는 정적 경로(CDN/S3 또는 `/static`)에서 받는다.
- 움직임은 `motion_key`(예: `motion.play`)로 표현하고, 실제 애니메이션 파일은 프론트 번들 또는 에셋 저장소에 둔다.

## 실시간 통신 (프로토콜 명세서 입력값)
| 필요 기능 | 마일스톤 | 후보 |
|---|---|---|
| 내 매물 판매 알림 (A-11) | M3 | SSE(`/api/v1/notifications/stream`) 또는 폴링 |
| 입찰식 경매 최고가 갱신 (A-10) | M3 | WebSocket(STOMP) |
| AI 펫 클라이언트와 상태 동기화 | v2 | 전용 API + 폴링/SSE |

> MVP(M1~M2)는 **REST만으로 충분**하다. 실시간 채널은 **SSE 1개**로 확정(D-9, `04_api/11_프로토콜_명세서.md`). AI 펫 클라이언트는 폴링. WebSocket은 입찰식 경매를 실제로 만들 때 재검토.

## 보안 원칙 — 로드맵 2 (AI 펫 부가 프로그램)
concept.md: "다른 사람들이 임의로 자기의 이미지를 넣을 수 없도록 관련 통신은 막아놔야겠다 / API 통신 안 보이도록".

1. **클라이언트에서 오가는 통신은 완전히 숨길 수 없다.** 사용자는 자기 컴퓨터의 네트워크를 언제든 볼 수 있다. 그래서 "숨기기"가 아니라 **"봐도 악용할 수 없게"** 설계한다.
2. **이미지를 받는 엔드포인트를 만들지 않는다.** 펫 외형은 `species + stage + 장착 아이템 ID`로만 표현하고, 서버에 등록된 에셋만 조합한다. 유저가 이미지를 보낼 방법 자체가 없게 만든다.
3. **서버가 외형을 결정한다.** 클라이언트는 "내 대표 펫 외형"을 요청할 뿐, 외형 값을 보내지 않는다.
4. **에셋은 서명 URL**(짧은 만료)로 내려준다. 무단 핫링크·대량 수집을 줄인다.
5. **AI 펫 클라이언트 전용 토큰**: 읽기 전용 스코프(`pet:read`)만 가진 별도 토큰을 발급해, 유출되더라도 거래·재화 API를 쓸 수 없게 한다.
6. 앱 바이너리에 비밀키를 넣지 않는다. 난독화는 보조 수단일 뿐이다.

## 참조 원본과의 차이 (API 단계에서 확정)
| 항목 | 참조 원본 | 현재 코드 | 제안 |
|---|---|---|---|
| 경로 접두사 | `/api/{resources}` | `/api/v1/...` | `/api/v1` 유지 |
| PK | Long | UUID (`members.id`) | 외부 노출 ID는 UUID 유지 |
| 성공 응답 | `ApiResponse<T>{success,message,data}` 래퍼 | 래퍼 없이 객체 그대로 | **✅ 래퍼 채택 (D-2)** — AuthController 수정 |
| 실패 응답 | `{success:false, error:{code,message}}` | `{code, message}` | **✅ 래퍼 채택 (D-2)** — SecurityConfig의 `writeError`도 같은 형식으로 |
| 비밀번호 해시 | BCrypt | PBKDF2 | 현재 유지 |
| JWT 라이브러리 | jjwt | spring-security-oauth2-jose | 현재 유지 |
| DB | MySQL | PostgreSQL | 결정 D-4 |
