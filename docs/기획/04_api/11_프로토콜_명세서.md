## 0. 채널 한눈에 보기
| 채널 | 방향 | 전송 | 마일스톤 | 용도 |
|---|---|---|---|---|
| REST `/api/v1/**` | C→S 요청/응답 | HTTPS JSON | M1 | 모든 명령·조회 (`01`~`10` 명세서) |
| 알림 스트림 `/api/v1/notifications/stream` | S→C 단방향 | SSE | M3 | 판매·만료·단계 상승 알림 |
| 에셋 `/assets/**` | C→S GET | HTTPS 정적 | M1 | 펫·아이템 이미지, 움직임 파일 |
| AI 펫 API `/api/v1/companion/**` | C→S | HTTPS JSON + 전용 토큰 | v2 | 데스크톱 위젯 등 외부 클라이언트 |

**원칙**
1. 상태를 바꾸는 명령은 **REST로만** 보낸다. SSE는 알림일 뿐이며, 클라이언트는 알림을 받으면 REST로 다시 조회해 진실을 가져온다.
2. 실시간 채널은 **하나(SSE)** 만 둔다. WebSocket은 입찰식 경매(M3 COULD)를 실제로 만들 때 재검토한다.
3. 모든 이벤트·페이로드는 JSON이고, 필드 추가는 자유·제거는 변경 박스 기록.

## 1. 알림 스트림 (SSE) — M3

### 1-1. 연결
```http
GET /api/v1/notifications/stream
Accept: text/event-stream
Authorization: Bearer <jwt>
Last-Event-ID: 1731760000123-0        (재연결 시, 선택)
```
- 브라우저 `EventSource`는 커스텀 헤더를 못 보내므로 클라이언트는 **fetch 기반 SSE**(예: `@microsoft/fetch-event-source`)를 쓴다. 쿼리스트링 토큰은 허용하지 않는다(로그 노출).
- 응답: `200 Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`.
- 회원당 동시 연결 **최대 3개**(탭 여러 개). 초과 시 가장 오래된 연결을 서버가 닫는다.
- 서버 구현: Spring `SseEmitter`, 타임아웃 **30분**. 만료되면 클라이언트가 재연결한다.
- 인증 실패는 401 JSON(`ApiResponse` 실패 형식)으로 응답하고 스트림을 열지 않는다.

### 1-2. 프레임 형식
```
id: 1731760000123-0
event: AUCTION_SOLD
data: {"type":"AUCTION_SOLD","id":"1731760000123-0","occurredAt":"2026-11-16T23:30:00+09:00","payload":{...}}

: heartbeat
```
| 필드 | 설명 |
|---|---|
| `id` | `<epochMillis>-<seq>`. 단조 증가. `Last-Event-ID`에 그대로 쓴다 |
| `event` | 이벤트 타입. `data.type`과 같다 |
| `data` | 한 줄 JSON. `payload`는 타입별 |
| `: heartbeat` | **20초**마다 주석 프레임. 프록시 타임아웃·끊김 감지용 |

### 1-3. 이벤트 카탈로그
| event | 발생 | payload | 클라이언트 권장 동작 |
|---|---|---|---|
| `CONNECTED` | 연결 직후 1회 | `{ "serverTime", "retryMillis": 3000, "missed": 0 }` | `missed > 0`이면 알림함 재조회 |
| `AUCTION_SOLD` | 내 매물이 팔림 | `{ "listingId", "itemCode", "itemName", "price", "fee", "sellerIncome", "buyerNickname" }` | 토스트 + 잔액·내 매물 재조회 |
| `AUCTION_EXPIRED` | 내 매물 만료 | `{ "listingId", "itemCode", "itemName", "price" }` | 토스트 + 인벤토리 재조회 |
| `AUCTION_REMOVED` | 관리자 내림 | `{ "listingId", "itemName", "reason" }` | 토스트 |
| `FAVORITE_SOLD` | 찜한 매물이 팔림/만료 | `{ "listingId", "itemName", "status" }` | 찜 목록 재조회 |
| `PET_LEVEL_UP` | 친밀도 단계 상승 (SSE로도 알림, P-5 응답에도 있음) | `{ "petId", "petName", "from", "to", "rewards": { "motions": [itemCode], "coins" } }` | 연출(이미 P-5 응답으로 처리했으면 무시: `id` 중복 체크) |
| `WALLET_ADJUSTED` | 관리자 재화 보정 | `{ "amount", "balance", "memo" }` | 잔액 재조회 |
| `NOTICE_PUBLISHED` | 새 공지 (전체 브로드캐스트) | `{ "noticeId", "title", "pinned" }` | 배지 |
| `SERVER_SHUTDOWN` | 배포 전 | `{ "reconnectAfterMillis": 10000 }` | 지정 시간 뒤 재연결 |

이벤트 발행 규칙: **트랜잭션 커밋 후** 발행(`@TransactionalEventListener(AFTER_COMMIT)`). 롤백된 거래의 알림이 나가면 안 된다.

### 1-4. 재연결·유실 복구
- 클라이언트 재연결 간격: `retryMillis`(3초)부터 **지수 백오프**(3→6→12→30초 상한), 성공하면 초기화.
- 서버는 회원별 **최근 이벤트 100건 / 24시간**을 저장한다(`notification_events` 테이블 또는 Redis 리스트). 재연결 시 `Last-Event-ID` 이후 것을 순서대로 다시 보낸 뒤 `CONNECTED`(`missed = n`)를 보낸다.
- 100건을 넘겨 유실됐으면 `CONNECTED.missed = -1`. 클라이언트는 알림함 REST(아래 1-5)로 전체를 다시 가져온다.
- 클라이언트는 `id`를 기억해 **중복 이벤트를 버린다**(at-least-once 전달).

### 1-5. 보조 REST (SSE와 짝)
| Method | Path | 설명 |
|---|---|---|
| GET | `/api/v1/notifications?page=&size=&unreadOnly=` | 알림함 (`PageResponse<Notification>`, 1-2 `data`와 같은 형식 + `readAt`) |
| PATCH | `/api/v1/notifications/read` | body `{ "ids": [..] }` 또는 `{ "all": true }` → 읽음 처리 |
> 이 2개는 `02_엔드포인트_목록.md` §12에 M3로 추가한다. `NOTICE_PUBLISHED`, `SERVER_SHUTDOWN`은 알림함에 저장하지 않는다.

### 1-6. 서버 측 배포 메모
- SSE는 장시간 연결이므로 Nginx Proxy Manager에 `proxy_buffering off`, `proxy_read_timeout 1800s`를 둔다(참조 원본 04 §1 토폴로지에 추가).
- 앱 인스턴스가 1대이므로 in-memory emitter 맵으로 충분하다. 2대 이상이 되면 Redis Pub/Sub으로 팬아웃한다.

## 2. 클라이언트 연출 프로토콜 — M1

> "서버가 결과를 정하고 클라이언트는 그 결과를 **재생**한다"는 원칙을 응답 필드 단위로 못 박는다. 서버 응답에 없는 값으로 화면을 그리지 않는다.

### 2-1. 펫 움직임 재생
- 모든 움직임은 **`motionKey`** 문자열로 식별한다. 형식 `motion.<name>`. 기본 세트:

| motionKey | 언제 | 비고 |
|---|---|---|
| `motion.idle` | 기본 대기 | 전 종 공통, 항상 존재 |
| `motion.sad` / `motion.normal` / `motion.happy` | `moodState`에 따라 idle 변형 | 없으면 `motion.idle` 폴백 |
| `motion.pet` / `motion.play` / `motion.eat` | P-5 응답 `motionKey` | 종에 해금 움직임이 있으면 서버가 그 키를 대신 돌려준다 |
| `motion.<species>.<name>` | 종별 해금 움직임 (MOTION 아이템 `assetKey`) | 예 `motion.duck.waddle` |
| `motion.levelup` | P-5 `levelUp != null` | |
| `motion.gacha.new` / `motion.gacha.refund` | G-2 `resultType` | |

- 재생 순서(P-5 기준): `motionKey` 재생 → `levelUp`이 있으면 `motion.levelup` → 해금 보상 카드 → `moodState`에 맞는 idle 복귀.
- 움직임 파일 해석: `motionKey` → 에셋 경로 `/assets/motions/<species>/<name>.<ext>` (3절). 파일이 없으면 `motion.idle`로 폴백하고 콘솔 경고만 남긴다(사용자 에러로 만들지 않는다).

### 2-2. 뽑기 연출 (G-2)
- `results[]`를 **`order` 순서**로 하나씩 공개한다. 회차마다:
  - `resultType = NEW_PET` → 희귀도별 이펙트(`rarity`) → `pet` 카드
  - `resultType = REFUND` → "이미 있는 친구" 카드 → `+refundCoins`
  - `pityTriggered` / `guaranteed` → 보장 뱃지
- 연출이 끝나기 전에 사용자가 건너뛰어도 상태는 이미 서버에 반영돼 있다(응답을 받은 시점). 연출 중 새로고침해도 유실되지 않는다.
- 연출 도중 재요청 방지: 응답을 받을 때까지 버튼 잠금, 같은 `Idempotency-Key`로만 재시도.

### 2-3. 슬롯 연출 (R-5)
- 릴 회전 애니메이션은 클라이언트 자유. **멈추는 심볼은 `reels[0..2]` 값으로만** 정한다.
- `tier`로 이펙트 등급을 정하고, `payout`·`net`·`wallet.balance`를 표시한다. 클라이언트가 배당을 계산하지 않는다.

### 2-4. 쿨다운·한도 표시
- 429 응답의 `Retry-After`(초)로 카운트다운을 그린다. 카운트다운이 끝나도 **서버 시각 기준**이므로 다시 429가 올 수 있다 → 그때는 새 `Retry-After`로 갱신한다.
- 날짜 경계(KST 00:00)는 `R-1.resetsAt`으로 받는다. 클라이언트 로컬 시계로 "자정"을 계산하지 않는다.

### 2-5. 기분(mood) 표시
- 응답의 `mood`, `moodState`를 그대로 쓴다. 클라이언트에서 시간 경과를 흉내 내어 깎지 않는다. 마이 홈 화면은 **5분 이상 머물면 H-1을 재조회**한다.

### 2-6. 낙관적 UI 금지 항목
잔액, 인벤토리 수량, 매물 상태, 뽑기 결과는 **서버 응답 전에 바꾸지 않는다**. 장착 변경(P-6), 찜(A-8/9)처럼 되돌리기 쉬운 것만 낙관적 갱신을 허용한다.

## 3. 에셋 전달 규약 — M1

### 3-1. 경로
| 종류 | 경로 | 예 |
|---|---|---|
| 펫 기본 이미지 | `/assets/pets/<speciesCode>/base.png` | `/assets/pets/duck/base.png` |
| 펫 실루엣 (도감 미보유) | `/assets/pets/<speciesCode>/silhouette.png` | |
| 펫 진화형 (M2, D-14) | 진화형도 독립 종이라 기본 이미지 경로를 그대로 쓴다 | `/assets/pets/duck_fire__water/base.png` |
| 아이템 | `/assets/items/<itemCode>.png` | `/assets/items/ribbon.png` |
| 움직임 | `/assets/motions/<speciesCode or common>/<name>.<ext>` | `/assets/motions/common/play.json` |
| 테마 | `/assets/themes/<itemCode>/{wall,floor}.png` | |

- API는 `assetKey`(경로에서 `/assets/` 뺀 값)만 돌려준다. 클라이언트는 `ASSET_BASE_URL + "/" + assetKey`로 조립한다. `ASSET_BASE_URL`은 빌드 환경변수(로컬 `http://localhost:8080/assets`, 운영 CDN/S3).
- 규격: 펫 512×512 PNG 투명 배경, 아이템 256×256, 움직임은 Lottie JSON 또는 스프라이트 시트(PNG + 같은 이름 `.json` 메타). 확정은 프론트 구현 시.
- 레이어 합성 순서(마이 홈): 테마 바닥 → 테마 벽 → 가구(`layer` 오름차순) → 펫 base → BOTTOM → TOP → ACCESSORY_1 → ACCESSORY_2. 장착 아이템은 펫 종과 무관하게 같은 앵커(펫 이미지 중심)에 겹친다(MVP).

### 3-2. 캐시
- 에셋은 불변으로 취급한다. 바꿔야 하면 **새 code**로 등록한다(`ribbon_v2`). 그래서 `Cache-Control: public, max-age=31536000, immutable`.
- 운영자 업로드 경로는 API에 없다. 에셋은 레포(`src/main/resources/static/assets` 또는 프론트 번들) 또는 S3에 배포 파이프라인으로 올린다.

### 3-3. 핫링크 방지 (v2에서 서명 URL로 강화)
MVP는 공개 정적 파일. v2에서 AI 펫 클라이언트를 열 때 4-4의 서명 URL로 전환한다.

## 4. AI 펫 클라이언트 통신 — v2 (설계만)

> 로드맵 2: "자신이 키운 펫을 AI 펫처럼 부가 기능을 제공하는 프로그램으로 띄운다". 외부 프로그램(데스크톱 위젯 등)이 서버와 통신하는 규약. **구현은 v2. 여기서는 MVP 설계가 이것을 막지 않도록 경계만 정한다.**

### 4-1. 위협 모델과 대응
| 위협 | 대응 |
|---|---|
| 남이 내 펫 이미지를 자기 것으로 바꿔 넣음 | **이미지를 받는 API가 없다.** 외형은 `species + stage + 장착 itemId` 조합이고 서버 카탈로그 에셋만 쓴다 |
| 위젯 토큰 유출로 거래·재화 조작 | 전용 토큰은 **읽기 스코프만**. 거래 API는 거부(403) |
| API 트래픽 관찰·재현 | 숨길 수 없음을 전제. 관찰해도 할 수 있는 일이 "내 펫 외형 조회"뿐이도록 설계 |
| 에셋 대량 수집·핫링크 | 서명 URL(짧은 만료) |
| 위젯 바이너리 역공학 | 바이너리에 비밀 없음. 토큰은 사용자가 로그인해 발급 |

### 4-2. 전용 토큰 (Companion Token)
```http
POST /api/v1/companion/tokens          ✅ USER (웹에서 로그인한 상태로 발급)
{ "deviceName": "내 노트북" }
→ 201 { "data": { "token": "cpt_...", "scope": ["companion:read"], "expiresAt": "+90d", "deviceId": "uuid" } }

GET    /api/v1/companion/tokens        ✅ 발급한 기기 목록
DELETE /api/v1/companion/tokens/{deviceId}   ✅ 폐기
```
- 토큰은 **불투명 문자열**(JWT 아님), 해시로 저장. 스코프 `companion:read` 고정.
- `/api/v1/companion/**` 외의 경로에서 이 토큰을 쓰면 403 `FORBIDDEN`.
- 웹 Access Token으로는 `/companion/state`를 호출할 수 없게 해 **두 토큰 체계를 분리**한다(유출 시 피해 범위 고정).

### 4-3. 상태 조회
```http
GET /api/v1/companion/state
Authorization: Bearer cpt_...
→ 200 { "data": {
    "pet": { "name", "species": { "code", "stage" }, "mood", "moodState", "affectionLevel",
             "equipment": { "TOP": "cloud_tee", "BOTTOM": null, "ACCESSORY_1": "ribbon", "ACCESSORY_2": null, "MOTION": "motion.duck.waddle" } },
    "assets": [ { "key": "pets/duck/base.png", "url": "https://.../pets/duck/base.png?X-Amz-Signature=...", "expiresAt": "+15m" }, ... ],
    "today": { "attendanceClaimed": false, "slotRemaining": 5 },
    "pollAfterSeconds": 300 } }
```
- 클라이언트는 `pollAfterSeconds` 간격으로 폴링한다. SSE는 열지 않는다(위젯 수만큼 장기 연결이 늘어나는 것을 피함).
- 위젯이 할 수 있는 상호작용은 없다(MVP v2). "쓰다듬기"를 위젯에서도 하고 싶으면 `companion:interact` 스코프를 따로 추가하고 P-5와 같은 쿨다운을 적용한다.

### 4-4. 서명 URL
- `assets[].url`은 **15분** 만료 서명 URL(S3 presigned 또는 자체 HMAC `?exp=&sig=`).
- 위젯은 에셋을 로컬 캐시하고, 401/403이면 `state`를 다시 조회해 URL을 갱신한다.

### 4-5. 레이트 리밋
| 대상 | 한도 |
|---|---|
| `/companion/state` | 토큰당 분당 12회 (`pollAfterSeconds` 무시 대비) |
| 토큰 발급 | 회원당 활성 10개 |
초과 시 429 `RATE_LIMIT_EXCEEDED`(에러 사전에 v2 섹션으로 추가 예정).

## 5. 버전·호환 규칙
- SSE 이벤트와 payload: 필드 **추가는 자유**, 제거·의미 변경은 새 이벤트 타입(`AUCTION_SOLD_V2`)으로.
- `motionKey`, `assetKey` 문자열은 계약이다. 바꾸면 새 code.
- 경로 버전은 `/api/v1`. 호환 불가 변경이 쌓이면 `/api/v2`를 열고 v1을 6개월 유지.
