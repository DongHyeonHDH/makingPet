# 00. 프로젝트 개요

> ⚠️ 2026-11-16 초안. 본 박스가 최신이며, 본문과 충돌하면 박스를 우선한다.
> 비유: **"다마고치 + 옷 입히기 인형 + 동네 벼룩시장"** — 뽑은 펫을 내 방에서 돌보고 꾸미고, 남는 옷과 가구는 다른 사람과 사고판다.

## 한 줄 정의
> **makingPet** — 허술하고 귀여운 펫을 뽑아 내 방(마이 홈)에서 꾸미고 상호작용하며, 플레이로 모은 코인으로 아이템을 사고파는 무과금 펫 키우기 웹 서비스.

## 왜 만드는가 (목적)
| # | 목적 | 성공 지표 (MVP 기준) |
|---|---|---|
| 1 | 펫을 뽑고 꾸미고 상호작용하는 **핵심 루프**를 완성한다 | 신규 유저가 가입 후 5분 안에 첫 뽑기 → 장착 → 상호작용까지 완료 |
| 2 | 유료 결제 없이 **매일 돌아올 이유**를 만든다 | 출석·미니게임 일일 참여율, 7일 재방문 |
| 3 | 유저 간 **아이템 경제(경매장)** 를 운영한다 | 거래 체결 건수, 재화 인플레이션이 관리 범위 안에 있음 |
| 4 | Spring Boot 모듈러 모놀리스로 **동시성·정합성**이 중요한 백엔드를 설계·구현한다 | 동시 구매·중복 보상 테스트 통과 |

**목적이 아닌 것**
- 유료 결제, 확률형 유료 아이템 판매 (재화는 전부 무료 획득)
- 실시간 멀티플레이 게임 (전투는 로드맵 3단계)
- 사용자가 직접 펫 이미지를 업로드하는 기능 (펫 이미지는 운영자가 제공하는 에셋만 사용)

## 사용자(페르소나)
| 페르소나 | Role | 핵심 기대 |
|---|---|---|
| 수집형 유저 | USER | 귀여운 펫을 모으고 도감을 채운다 |
| 꾸미기형 유저 | USER | 펫 옷과 방을 꾸미고 다른 사람에게 보여준다 |
| 거래형 유저 | USER | 경매장에서 싸게 사고 비싸게 팔아 코인을 모은다 |
| 운영자 | ADMIN | 펫·아이템·뽑기 확률·공지사항을 관리한다 |
| 최고 관리자 | SUPER_ADMIN | 운영자 권한 부여, 재화 보정 |

권한 위계: `SUPER_ADMIN > ADMIN > USER`

## 핵심 도메인
```
member     회원가입, 로그인, 프로필 (현재 코드의 auth 패키지)
pet        펫 종(species) 카탈로그, 보유 펫, 상호작용, 기분·친밀도
gacha      뽑기 풀, 확률표, 뽑기 실행, 천장(보정) 카운트, 뽑기 기록
item       아이템 카탈로그(의상·움직임·가구), 인벤토리
home       마이 홈: 펫 장착(상의·하의·악세서리·움직임), 방 테마·가구 배치, 공개 여부
wallet     코인 잔액과 원장(거래 기록)
reward     출석, 가위바위보(1일 1회), 빠칭코(슬롯, 1일 N회)
shop       운영자 판매 상점 (고정가)
auction    유저 간 경매장: 등록, 검색, 즉시구매, 찜, 시세, 정산
community  공지사항, (선택) 게시판·댓글
admin      운영 도구 (카탈로그·확률·공지·재화 보정)
```

## 용어집 (핵심만, 상세는 [01_용어집](./01_용어집.md))
| 용어 | 정의 |
|---|---|
| 펫 종(Species) | 운영자가 정의한 펫의 원형. 이미지·희귀도·기본 움직임을 가진다 |
| 보유 펫(UserPet) | 유저가 뽑기로 얻은 펫 한 마리. 이름·기분·친밀도·장착 상태를 가진다 |
| 대표 펫 | 마이 홈과 프로필에 나오는 펫 1마리 |
| 마이 홈 | 펫을 꾸미고 상호작용하는 개인 공간이자 개인 페이지 |
| 코인 | 유일한 재화. 무료로만 획득한다 |
| 매물(Listing) | 경매장에 올린 판매 등록 1건 |

## 로드맵 (concept.md 기준)
| 단계 | 내용 | 이 문서의 범위 |
|---|---|---|
| 1 | 펫 뽑기, 꾸미기, 상호작용 + 재화·상점·경매장 | **이번 기획의 본 범위 (M1~M3)** |
| 1.5 | 육성·진화 (열매·장비로 5단계 이상 진화) | v1.1 — 데이터 구조만 미리 열어둔다 |
| 2 | 내 펫을 AI 펫(데스크톱 위젯 등)으로 띄우는 부가 프로그램 | v2 — 보안 원칙만 아키텍처 문서에 정리 |
| 3 | 속성·기술 조합 전투 | v3 — 범위 외 |

## 캐릭터 아트 방향
- 무드: "조금 허술하고 멍한 귀여움". 고라파덕·모찌·치이카와 같은 **느낌**을 참고한다.
- **원칙: 기존 캐릭터를 복제하거나 닮게 만들지 않고 오리지널 캐릭터만 사용한다.** 기존 IP와 닮은 이미지는 저작권·상표 분쟁 위험이 있다.
- 현재 시안: `docs/pet-character-portraits/` (cat, dog, duck, dinosaur).
- 에셋 규격(제안): 정면 기본 포즈 PNG(투명 배경, 512×512) + 움직임별 스프라이트 시트 또는 Lottie. 확정은 프론트 구현 시점에 한다.

## 비기능 요구
| 항목 | 목표 |
|---|---|
| 응답시간 | 일반 API p95 < 300ms, 뽑기·구매 p95 < 500ms |
| 동시 사용자 | 개인 프로젝트 기준 동시 100명 수준 |
| 정합성 | 재화와 아이템은 어떤 동시 요청에서도 음수가 되거나 복제되지 않는다 |
| 공정성 | 확률은 서버에서만 계산하고, 확률표는 유저에게 공개한다 |
| 보안 | Stateless JWT, 비밀번호 해시(PBKDF2, 현재 코드), 관리자 API 분리 |
| 관측성 | 재화 원장과 뽑기 기록으로 사후 추적이 가능해야 한다 |
| 배포 | Docker Compose (참조 원본 04 인프라 양식) |
